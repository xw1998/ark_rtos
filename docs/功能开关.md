# Ark RTOS 功能开关

## 一句话

内核里每一块"不是每个系统都要"的功能，都有一个开关；开关的表在
`kernelsrc/include/arkrtos_features.h`。关掉以后不是"编不过"，而是那块功能
不存在，并且**它对外说的每一个字都是实话**。

## 怎么用

三种改法，任选一种：

1. 直接改 `arkrtos_features.h` 里的默认值（简单，但会出现在 diff 里）
2. 在 `arkrtos_config.h` 之前定义，覆盖默认值：
   ```c
   #define ARKRTOS_USE_FS   0
   #include "arkrtos_config.h"
   ```
3. 工程宏（Keil：Options → C/C++ → Define）：
   `-DARKRTOS_USE_FS=0 -DARKRTOS_USE_MDK_TRACE=0`

`arkrtos_features.h` 里每一项都是 `#ifndef / #define / #endif`，所以外部定义
永远优先。

## 开关分三层，不要混

| 层 | 管什么 | 放哪 | 例子 |
|---|---|---|---|
| 能力层 | 这颗芯片**有**什么 | 板级配置 `board/*/arkrtos_board_config.h` | `ARKRTOS_USE_FPU` / `ARKRTOS_USE_MPU` / `ARKRTOS_USE_PRIV` |
| 选配层 | 这次构建**要**什么 | `arkrtos_features.h` | 本文下面全部 |
| 既有配置 | 早就存在、另有一个名字 | `config/arkrtos_partition.h` | `SHELL_ENABLE` / `INSTALLER_ENABLE` |

能力层描述硬件事实，选配层描述软件取舍 —— 一个开关只能属于一层。
Shell 的开关**不在** `arkrtos_features.h`：它叫 `SHELL_ENABLE`，在
`config/arkrtos_partition.h`，`arkrtos_shell.c` 的整文件门控与关闭时的空实现
一直在那儿。不要在 `arkrtos_features.h` 里再写一个 shell 开关。

## 开关清单

### 一、内核基础机制

| 开关 | 关掉后 |
|---|---|
| `ARKRTOS_USE_SPINLOCK` | 自旋锁换成**纯关中断**的降级实现（单核够用，省掉原子 CAS 与 SMP 预留）。锁语义仍在，调用方不用改 |
| `ARKRTOS_USE_SCHED_LOCK` | **不允许关**（置 0 直接 `#error`）。锁语义没有诚实的降级方式，见下文 |
| `ARKRTOS_USE_STACK_USAGE` | 不再统计每任务栈峰值（少了建任务时的水印填充与扫描）；`task` 命令那一列打印 `n/a`。`stack` 命令**仍注册**，但只回一行 `stack: accounting is compiled out (ARKRTOS_USE_STACK_USAGE=0) - no numbers to show`——不给编造的数字 |
| `ARKRTOS_USE_STACK_CHECK` | 不再做栈尾标志检查 |
| `ARKRTOS_USE_SCHED_STAT` | 调度统计归零（上下文切换次数等） |
| `ARKRTOS_USE_CPU_LOAD` | 不再可查询 CPU 占用 |
| `ARKRTOS_USE_FAST_TICK_SWITCH` | 关掉"按需拉 PendSV"的快速路径，回到每个节拍都判定 |
| `ARKRTOS_USE_TICKLESS` | 空闲时不再合并节拍，回到一拍一次 `WFI`（每个 500 µs 都被叫醒一次）。默认关；`arkrtos_tickless.c` 编出空目标，tick handler 与 `ARKRTOS_WFI()` 都还是原来那份代码，**体积与行为零变化**。上限见 `ARKRTOS_TICKLESS_MAX_TICKS`（默认 8 拍）。见 [低功耗与 tickless](低功耗与tickless.md) |
| `ARKRTOS_USE_FAULT_RECOVER` | 故障发生后不再尝试恢复调度 |
| `ARKRTOS_USE_MPU_APPLY_CACHE` | MPU 上下文缓存不生效：任务每次切入都整套重写 MPU 寄存器（更慢，语义不变） |

### 二、同步与 IPC

| 开关 | 关掉后 |
|---|---|
| `ARKRTOS_USE_MEMPOOL` | 固定块内存池不存在：创建失败、分配一律返回 0，SVC 0x20 一律返回 -1（调用者另想办法，不会给一块会碎的内存）。见 [固定块内存池](固定块内存池.md) |
| `ARKRTOS_USE_MQ` | 消息队列服务不存在：创建失败、收发一律拒绝（不会给一个"静默丢消息"的句柄） |
| `ARKRTOS_USE_TIMER` | 软件定时器不存在：创建/启动一律拒绝，回调永远不会被"答应" |
| `ARKRTOS_USE_SBUF` | 流缓冲 / 消息缓冲不存在：`arkrtos_sbuf.c` 编出空目标，SVC 0x1F 一律返回 -1。默认关（每块缓冲静态占 `ARKRTOS_SBUF_BUF_SIZE` 字节 x `ARKRTOS_SBUF_NUM`）。见 [流缓冲与消息缓冲](流缓冲与消息缓冲.md) |

### 三、服务与组件

| 开关 | 关掉后 |
|---|---|
| `ARKRTOS_USE_LOG` | 内核日志与控制台一起消失。用户态往控制台句柄写会**走普通设备路径**（`arkrtos_console_is_handle()` 返回 0），不是写进黑洞 |
| `ARKRTOS_USE_LOG_RING` | dmesg 环形日志不存在：shell 的 `dmesg` 命令一起消失，历史日志无法事后回看（若 `ARKRTOS_USE_LOG=1`，实时输出仍在） |
| `ARKRTOS_USE_BLK` | 块设备层空表，任何读写返回 -1。**依赖：`ARKRTOS_USE_FS` 必须同时为 0** |
| `ARKRTOS_USE_FS` | 文件系统门面一律"什么都没挂载"，错误码与真实情况一致 |
| `ARKRTOS_USE_VFS` | 路径命名空间不存在：`/dev`、`/mnt` 都找不到了，shell 的 `mount` / `ls` / `cat` 与 App 的按路径访问一律 `NOSYS`。**依赖：`ARKRTOS_USE_BLK` 必须为 1** |
| `ARKRTOS_USE_VFS_LFS` | `/mnt` 下不再自带持久卷：内核不把块设备窗口桥成 littlefs 卷，调用者仍可自己挂 `fsdrv`。**依赖：`ARKRTOS_USE_VFS`** |
| `ARKRTOS_USE_PROCFS` | `/proc` 不存在：`version` / `uptime` / `meminfo` 等内核状态不再能按路径读取。**依赖：`ARKRTOS_USE_VFS`** |
| `ARKRTOS_USE_POSIX` | App 不能再用 `<pthread.h>` 那一套，只能用原生 oslib |
| `ARKRTOS_POSIX_WRAP_STDLIB` | POSIX 层不再把 `malloc/free` 接到自己的堆（默认就是关的） |
| `ARKRTOS_USE_MINIAPP` | 小程序功能消失：没有"从文件系统读进 RAM 就执行"的第三种应用，shell 的 `mini` 命令一起消失。**依赖：`ARKRTOS_USE_FS`** |
| `ARKRTOS_MINI_MAX` | 并发小程序数量（编译期上限，1..4，默认 2）：设超范围直接 `#error`，不是"静默截断" |
| `ARKRTOS_MINI_YIELD_CHUNKS` | `0` = 整段装载期间一直持调度器锁，体积与行为退回本开关引入前；默认 `1` = 每读一个分块让出一次调度器，装载期间控制回路不被整段冻结 |
| `ARKRTOS_USE_MDK_TRACE` | trace 采集整体消失，14 个入口变成空实现 |
| `ARKRTOS_USE_SOFTBUS` | 跨设备软总线整体不进二进制：没有事件 / 远程调用 / 数据平面，shell 的 `bus` 命令一起消失。默认关；打开时工程侧必须同时给出 MCU 档 `-DARK_BUS_*`，否则编译期 `#error` |
| `ARKRTOS_USE_LWIP` | lwIP 端口层不参与编译：没有 socket/select 的底座，也不注册那个 1 KB 栈的服务任务。**默认就是关的**（内核区要多占 128 KB，见 [lwIP协议栈接入](lwIP协议栈接入.md)） |

### 四、可靠性运维

| 开关 | 关掉后 |
|---|---|
| `ARKRTOS_USE_IMAGE_SIGN` | 安装时不校验签名：任何能写进槽位的镜像都会被接受。**开它必须提供 `ARKRTOS_IMAGE_SIGN_KEY`（32 字节），否则编译期报错**。默认关（对称 HMAC 方案，不构成完整信任链） |
| `ARKRTOS_USE_CRASH_LOG` | 跨复位崩溃账本不存在：不记录、不因故障次数禁用镜像、区域地址为 0 |
| `ARKRTOS_HW_SAFE` | App 崩溃时的硬件安全态（"遗言"）机制整体不进二进制：设备 open/close 与任务收尸路径与引入前完全一致。关掉后 SVC 0x14 sub 4/5/6 不存在，SVC 0x10 sub 6 明确返回 -1。默认关 |
| `ARKRTOS_MINI_EXIT_IS_HANDOVER` | `0` = 小程序主任务正常退出也执行遗言 / 回调，硬件立刻回安全态（无缝升级时出现一次抖动）；默认 `1` = 正常退出只摘台账，把设备交给马上接手的新版本。仅在 `ARKRTOS_USE_MINIAPP=1` 时有意义 |
| `ARKRTOS_USE_KERNEL_GUARD` | 心跳契约关掉：记录是空操作，**显式心跳返回 -1 被拒绝**（不让调用方以为"有人在看着"） |
| `ARKRTOS_USE_AUDIT` | 结构化自检关掉：报告为空、掩码 0，看到的是"无发现"而不是伪造的健康证明 |
| `ARKRTOS_USE_UTEST` | 板端单元测试框架与 shell 的 `utest` 命令都不参与编译，体积与行为零变化 |
| `ARKRTOS_USE_CM_BACKTRACE` | 异常回溯组件不参与编译 |

### 五、板上直跑相关（例程 Makefile 开关）

这一层不是内核能力，而是**这次构建里到底编进了哪几个"让板子自己编、自己跑"的部件**。
开关都在 `example/stm32h743/kernel/ARKRTOS_TEST/GCC/Makefile` 顶部，写进 `DEFS`，
关掉时对应源文件**根本不参与编译**。

| 开关 | 关掉后 |
|---|---|
| `USE_ARKVIM` | 板上的 `vim` 命令消失（编辑器不进二进制） |
| `USE_ARKC` | 板上的 `cc` 命令消失（板上编译器不进二进制）。它要求 `ARKRTOS_USE_VFS=1`，组合不成立时编译期 `#error` 拦住，不在链接期才炸 |
| `USE_APPRUN` | `app run` 那条固定 RAM 窗口的直跑入口消失，`arkrtos_apprun.c` 编出为空目标 |
| `USE_ARKMAKE` | 板上的 `make` 命令消失（工程描述构建器不进二进制）。它要求
`USE_ARKC=1` 且 `USE_APPPACK=1`——`make` 的打包回调就是 `cc --pack` 的本体，
组合不成立时 `arkrtos_features.h` 的 `#error` 在编译期拦住 |
| `USE_APPPACK` | `cc --pack` 报 `option '--pack' is not supported by this build`：四遍差分打包器不进二进制，**`.svcm` 也就无从产生** |
| `USE_MINI_VFS` | `mini run` 退回从 `arkrtos_fs` 卷读镜像（与引入开关前逐字节一致）；**要读 `/mnt/...` 这种挂载点路径就必须开** |
| `USE_QSPI` | 不碰 QUADSPI 的时钟与引脚，`drvqspi.c` 不编译、`nor` 命令消失、`nor0` 块设备不注册；**2026-11-07 起它还决定 `/mnt/nor` 上电是否自动挂载**（`ARKRTOS_AUTOMOUNT_NOR=$(USE_QSPI)`）：工程文件常驻 NOR，`cd /mnt/nor && make` 就是演示主线，不再需要先敲 `fs mount` + `mount` |
| `USE_SDRAM` | 外置 SDRAM 不启用，编译器缓冲与 ramfs 留在片内（默认关）。**2026-11-07 起真机可用**：缺的是 `FMC_BCR1.FMCEN`，补上后 `sdram test` 全 32 MB 读写 PASS，`USE_SDRAM=1` 档片内 RAM 从 98.37% 降到 62.14%、编译器池 80 KB→4 MB。开关打开时启动会先验证窗口再挂 VFS（`ARKRTOS_SDRAM_VERIFY_AT_BOOT`，默认 1） |
| `ARKRTOS_PACK_IN_EXTRAM` | `cc --pack` 的四份 16 KB 负载 + 16 KB 对象/镜像缓冲退回片内 RAM 池借用（板级宏跟 `USE_SDRAM` 走）。默认 0 时与本开关出现之前**逐字节相同**；打开后整块 80 KB 落 `.extram`（SDRAMFS 分区 NOLOAD），窗口也从 8 KB 抬到 16 KB——四个源大约 7.7 KB 负载，8 KB 窗装不下 |
| `ARKRTOS_AUTOMOUNT_NOR` | 上电不挂 NOR 卷（不打印、不碰 littlefs/VFS 挂载路径）。默认 0；要它必须 `USE_QSPI=1` + `USE_FS=1` + `USE_VFS=1` + `USE_VFS_LFS=1`，否则 `#error` |
| `MINI_PRIORITY` | 空 = 沿用内核默认 `APP_TASK_PRIORITY`(10)，**在控制台(14)之上**：一个 `for(;;)` 的小程序会把 shell 永久饿死，`mini run` 之后连提示符都不回来，只能复位（本轮实测）。本演示/回归工程默认 **20**（与 `ARKRTOS_APPRUN_PRIORITY` 同一条规则），要复现内核默认行为：`make MINI_PRIORITY=` |

> `make` **不跟踪 `-D` 与头文件改动**：换开关或改分区头之前必须 `make clean`，
> 否则会拿旧目标文件链出一个"看起来对、其实开关没生效"的镜像。
> （2026-11-07 起这条已有机械兜底：所有会改变镜像的开关值写进 `build/.ldcfg`

> （`ARK_RAMFS_FILE_CAP` / `ARK_RAMFS_MAX_FILES`）也进了指纹，因为改它们就是改

## 两条实现规则

**规则一：被内核热路径调用的模块，用「整文件门控 + `#else` 空实现」。**
`tick`、`SVC` 分派、设备写这些地方不该散落 `#if`，否则代码读起来像打了补丁。
现在这些模块的 stub 一律回答"没有"：失败返回 -1，查询返回 0、NULL 或 `n/a`。
绝不返回一个看着像成功的值。

**规则二：必须为 1 的开关，用 `#error` 挡住，不要留给链接器。**
`ARKRTOS_USE_SCHED_LOCK` 就是这样：内核侧调用点没有关闭分支，置 0 会让 14 个
符号在链接期才炸。`ARKRTOS_USE_FS=1 && ARKRTOS_USE_BLK=0` 同理。依赖关系写在
`arkrtos_features.h` 末尾，让编译器在最前面就把话说明白。

## 怎么验证"真能关"

```bash
# 全部选配开关置 0（ARKRTOS_USE_SCHED_LOCK 除外，它必须为 1）
python3 - <<'PY'
import re, io
p = "kernelsrc/include/arkrtos_features.h"
t = io.open(p, encoding="utf-8", newline="").read()
out = []
for l in t.split("\n"):
    m = re.match(r"(#define (ARKRTOS_USE_[A-Z_0-9]+)\s+)\S+\s*$", l)
    if m and m.group(2) != "ARKRTOS_USE_SCHED_LOCK":
        l = m.group(1) + "0"
    out.append(l)
io.open(p, "w", encoding="utf-8", newline="").write("\n".join(out))
PY

# 编译（注意 -o 落 C:\tmp，退出码 1 只是 warning）
UV4 -r <工程>.uvprojx -o C:\tmp\trim.log -j0
```

判据是 **0 Error(s)**，并且生成 `.axf`。跑完记得把 `arkrtos_features.h` 还原。

本次实测（STM32F427 内核工程，全部选配开关关闭，Shell 仍启用）：

| 配置 | Code | RO-data | RW-data | ZI-data |
|---|---|---|---|---|
| 全开（基线） | 92206 | 7154 | 416 | 51524 |
| 全部选配关闭 | 55530 | 4022 | 316 | 36516 |

代码量降到 **60.2%**。这个数字的意义不是"省了多少"，而是证明这些开关
真的把代码拿掉了，而不是写着好看的假开关。

## 新增一个开关的清单

1. 在 `arkrtos_features.h` 对应分组里加 `#ifndef / #define / #endif`
2. 在实现文件里加整文件门控，并在 `#else` 写清"关掉以后调用方看到什么"
3. 若它被内核调用，确认关闭后仍有符号可链（stub），或写明"必须为 1"加 `#error`
4. 跑一次"全关"编译，确认 0 Error
5. 跑一次全开编译，确认 Code 与基线一致


## 和 Kconfig 的分工

上面三种改法仍然有效，但更推荐用 Kconfig 统一决定这些开关的取值：

* `arkrtos_features.h` 仍是代码里 `#if ARKRTOS_USE_XXX` 的落脚点；
* **Kconfig 负责决定**这些宏取什么值，并保证取值之间处于合法组合（例如
  `ARKRTOS_USE_FS` 依赖 `ARKRTOS_USE_BLK`）。

生成的头文件 `kernelsrc/include/arkrtos_autoconf.h` 里每个宏都包了 `#ifndef`，
所以工程宏（上面第 3 种改法）依然能覆盖它。具体菜单、工具与用法见
[Kconfig配置系统.md](Kconfig配置系统.md)。

顺带一提：原先散在各处写死的数量上限（任务表/同步表/队列/定时器/socket/fd 等）
现在也都成了 Kconfig 符号，默认值和过去完全相同——不跑 Kconfig 时行为零变化。
