# arkvim 编辑器显示约定

`vim` 命令背后是 `kernelsrc/components/arkvim`，它是上游仓库
`D:/工作/git_project/arkvim`（gitee：`xw19981010/ark-vim`）的 vendored 副本。

这份文档只讲**屏幕上应该看到什么**、以及每条约定用什么办法证明它成立。
上游的键位、命令、搜索实现不在这里。

---

## 1. 屏幕布局

| 行（0 基） | 内容 |
|---|---|
| `0 .. 21` | 编辑区，22 行 |
| `22` | 状态行：`-- COMMAND --  <文件名>  <行数>L`，或插入模式的提示 |
| `23` | 命令行：`:`、`/` 与后续输入都画在这一行 |

`ARKVIM_SCREEN_ROWS=24`、`ARKVIM_SCREEN_COLS=80`。
屏幕是 80×24 的固定网格，窗口尺寸变化不在支持范围内。

行号栏（gutter）默认**开**，宽度 = 最大行号的位数 + 1 个分隔空格，最少保 3 位
（小文件也占 4 列，这样正文不会因为文件变长而左右跳），到 1000 行变 5 列、
10000 行变 6 列。编辑区的第 0 列是行号栏，正文从 `gutter_width` 开始；
文件短时看到的是 `  1 ` 这样 4 列。

## 2. 五条显示约定

### 2.1 一帧没有变化，就一个字节都不发

刷新走双缓冲 + 脏行判定，只有真的变了的格子才会变成输出。
光标状态（`ESC[?25l` / `ESC[?25h`）也一起记账：终端已经知道的位置和可见性
不再重复发。

**为什么定这条**：以前每次刷新都无条件重发一遍「隐藏光标 + 显示光标」，
在 MobaXterm 上就是光标每秒闪十来次——用户报的「光标闪烁异常」就是这个。

**判据**：串口在空闲期必须**零字节**。板上实测（`rawcap.py`，按时间戳记录每
一个字节）：打开 `/mnt/nor/hello.c` 整屏画完是 `t=1.569`，之后到 `t=5.309`
我按下 `:` 之前，**3721 ms 零字节**。

### 2.2 命令行只画一次前缀

命令缓冲里 `cmd_buf[0]` 本来就是触发的 `:` 或 `/`，`cmd_len` 含它，
`exec_ex()` 里还会 `if (cmd[0] == ':') cmd++;`。所以画前缀的代码**只能画一
次**——上游 `a8fd82e` 之前是「画一次前缀，再把含前缀的整行拷一遍」，
屏幕上就成了 `::q`。

**判据**：板上按 `:` 只发 `ESC[24;1H ESC[0m :`（一个冒号），按 `q` 只发
`ESC[24;2H q`；host 门禁 2 直接要求输出里不出现 `::`。

### 2.3 行号默认开，gutter 跟着位数长

行号栏默认显示，方便对照编译器报的行号；`1000` 行以上自动从 2 格变 3 格，
正文不会因为「数字变宽」而错位。

### 2.4 控制字节不许当字形画

`0x00..0x1F` 与 `0x7F` 一律画成 `?`。包括 **CR** 和 **TAB**。

**为什么定这条**：板上的 `echo` 写文件用的是 CRLF，CR 在 gap buffer 里就是
一个普通字节。原样发给终端，终端会把光标拉回第 1 列，整行被撕开，之后定位
光标的那条 `ESC[y;xH` 又落到行号栏上——看起来像「显示错乱」。

板上实测（文件内容 `line one\0x0D line two` / `x\0x09y` / `ctl\0x01z`）：
终端收到的 CR 0 次、TAB 0 次、`0x01` 0 次，三处都是 `?`，之后 1.5 s 空闲
0 字节。

### 2.5 光标只在状态真的变了才 hide/show

写操作期间光标藏着（避免它停在半画好的格子上），画完立刻还给它。
终端自己的闪烁（通常 1~2 Hz）是终端行为，不是编辑器在发字节。

## 3. 已知限制

- **TAB 不展开**：按 2.4 的规则画成 `?`。Makefile 里用 TAB 缩进是硬需求，
  这一类文件在编辑器里看到的 `?` 就是 TAB 本身，`make` 仍然正常。
- **没有 wcwidth**：编辑区按「一个字节一格」排，UTF-8 多字节字符（中文）会
  占好几格。含中文的文件在本编辑器里排版会错位，这是既有实现，没有改。
- **不做换行**：长行只在右边界截断显示，不会折到下一行。

## 5. 改这个组件的方式

`kernelsrc/components/arkvim/src/` 是 vendored 副本，**不许手改**——改了会在
下一次同步被覆盖，而且上游门禁根本看不到。

流程：

```bash
cd "D:/工作/git_project/arkvim"        # 改源码 + 加/改 tests/ 门禁 + make test
git commit && git push origin master

cd "D:/工作/git_project/Ark RTOS"
python tools/sync_arkvim.py --apply    # 只拷 src/*.c src/*.h，重写 VENDOR.md
```

一个会静默骗人的坑：`shutil.copy2` 连 mtime 一起搬。源仓库某个文件最后一次
改动可能比目标 `.o` 还新不到哪去，`make` 于是判定「不用重编」，产物的
text/bss 一个字节都没变，看着像「同步生效了」。`sync_arkvim.py` 现在复制完
会 `os.utime(dst, None)`；同步后仍然建议对一次构建体积（见下表）。

当前同步点：源 commit `0c4cb1c`，FLASH 461800 B（88.08%）、RAM 285900 B
（63.45%）、SDRAMFS 5849888 B（92.98%）。
