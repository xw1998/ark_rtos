# Stream buffer and message buffer (`arkrtos_sbuf` / `arkrtos_mbuf`)

**[简体中文](流缓冲与消息缓冲.md) | English**

> Condensed English edition. The Chinese page (流缓冲与消息缓冲.md) is normative: every number below is
> copied from it as of 2026-11-18, but if the two disagree, the Chinese page wins. This page adds no
> new claim and no new measurement.

In one line: **one static buffer, two usages** — byte-stream send/receive (can take half a message), or
length-header-framed messages (whole message atomic). Default **off** (`ARKRTOS_USE_SBUF=0`).

- kernel implementation: `kernelsrc/src/arkrtos_sbuf.c` (the whole file is wrapped in
  `#if (ARKRTOS_USE_SBUF == 1)`)
- kernel-internal header: `kernelsrc/include/arkrtos_sbuf.h`
- public API: `@defgroup sbuf` in `kernelsrc/include/arkrtos.h`
- App-side wrapper (through SVC): `kernelsrc/sdk/app_sdk/arkrtos_oslib.c`
- host regression: `kernelsrc/tests/test_sbuf_host.c` + `tools/sbuf_host_gate.py`
- on-board cases: `sbuf_stream_contract` and `mbuf_framing_contract` in
  `kernelsrc/src/arkrtos_utest_cases.c` (both cases sit entirely inside
  `#if (ARKRTOS_USE_SBUF == 1)`: with the switch off they are not in the board case table)

## 1. Two semantics, never mixed

| | stream buffer `arkrtos_sbuf_*` | message buffer `arkrtos_mbuf_*` |
|---|---|---|
| unit | bytes | one message (4-byte length header + payload; header width set by `ARKRTOS_MBUF_HDR_BYTES`) |
| send | **may partially succeed**: writes as much as fits, returns the actual byte count | **whole message atomic**: either all of it goes in or not a byte |
| receive | reads as much as is there | one message at a time; if the buffer is too small the whole message is **discarded** and `ARKRTOS_SBUF_ERR_TOO_SMALL` returned |
| typical use | ISR pushes bytes, a task takes them in batches (UART receive) | delimited messages (commands, events, one protocol frame) |

> **Do not mix both API sets on the same buffer.** Messages are delimited by the length header; once
> raw bytes are mixed in, the header goes out of alignment and every later `mbuf_recv` reads "a
> length" from inside the payload. This is not defensive nagging, it is the only usage constraint of
> this implementation.

## 2. Interface

| Interface | Meaning |
|---|---|
| `int32 arkrtos_sbuf_create(char *name)` | create (name max 7 bytes). Static object table, negative on failure |
| `int32 arkrtos_sbuf_send(h, buf, len, timeout_ms)` | write bytes, returns the **actual** bytes written; `timeout_ms` 0 = no wait, negative = wait forever |
| `int32 arkrtos_sbuf_recv(h, buf, len, timeout_ms)` | read bytes, returns the actual bytes read |
| `int32 arkrtos_sbuf_send_from_isr(h, buf, len)` | write from an interrupt, non-blocking, negative when full |
| `int32 arkrtos_sbuf_used(h)` / `arkrtos_sbuf_free(h)` | bytes stored / remaining |
| `int32 arkrtos_sbuf_reset(h)` | clear (and wake writers waiting for space) |
| `int32 arkrtos_sbuf_delete(h)` | delete (waiters receive "object deleted" and never sleep until timeout) |
| `int32 arkrtos_mbuf_send(h, buf, len, timeout_ms)` | send one message, 0 = the whole message was written |
| `int32 arkrtos_mbuf_recv(h, buf, len, timeout_ms)` | receive one message, returns its length |
| `int32 arkrtos_mbuf_send_from_isr(h, buf, len)` | send one message from an interrupt |
| `int32 arkrtos_mbuf_peek_len(h)` | length of the next complete message (negative if none), so the caller can size its buffer first |

Return codes: `ARKRTOS_SBUF_OK 0`, `ARKRTOS_SBUF_ERR_PARAM -1`, `ARKRTOS_SBUF_ERR_TIMEOUT -2`,
`ARKRTOS_SBUF_ERR_DELETED -3`, `ARKRTOS_SBUF_ERR_NOSPC -5`, `ARKRTOS_SBUF_ERR_TOO_SMALL -6`.

**Why -4 is deliberately skipped**: `ARKRTOS_SYNC_ERR_WOULDBLOCK (-4)` is the user-state wrapper's
internal "must wait more" signal. Encoding NOSPC as -4 as well would make the App-side polling wrapper
treat it as "keep waiting", turning "this message can never fit" into "wait forever".

**Why a too-small `recv` discards the whole message**: leaving half a message in the buffer makes the
next `recv` read the first payload bytes as a length header and the whole stream stays misaligned
forever. Losing one message is bad news; reading a pile of wrong lengths is a bad system.

**Why a `send` larger than the whole buffer is NOSPC immediately**: a write bigger than the whole
buffer will never fit no matter how long you wait, so timeout semantics are meaningless there.

## 3. Configuration

```c
/* kernelsrc/include/arkrtos_config.h */
#define ARKRTOS_SBUF_NUM       (4)     /* number of objects */
#define ARKRTOS_SBUF_BUF_SIZE  (256)   /* bytes per buffer */
#define ARKRTOS_MBUF_HDR_BYTES (4)     /* length header width, 2..4 */
```

```c
/* kernelsrc/include/arkrtos_features.h, default 0 */
#define ARKRTOS_USE_SBUF 0
```

Kconfig has a same-named symbol `ARKRTOS_USE_SBUF` (`config/kconfig/Kconfig.features`), generated by
`tools/kconfig/genconfig.py` into `arkrtos_autoconf.h`.

Cost with the switch off: `arkrtos_sbuf.c` produces an **empty object** (measured `text 0 / data 0 /
bss 0`), SVC 0x1F always returns -1, and the image and command table are byte-identical.

## 4. Implementation conventions

- **Ring region**: monotonic `rd`/`wt` indices with manual wrap (the buffer size need not be a power of
  two, so no bit masking), with `count` deciding empty/full — when full, `wt` may equal `rd` and
  `count == size` is still correct.
- **Blocking/waking**: same scheme as `arkrtos_mq`. All state changes happen inside an
  interrupt-disabled critical section; when there is no space/data the current task is first
  registered in the wait table and then `arkrtos_task_block_in_critical()` is called **inside the same
  critical section** (register before sleeping, otherwise an ISR wake would be delivered to a task
  that has not slept yet = a lost wake). Being woken does not mean getting the resource: on wake it
  re-checks and re-sleeps with the remaining timeout.
- **User state**: through `ARKRTOS_SVC_SBUF_CTRL (0x1F)`, 24-byte argument block, subcommands 1..12.
  A non-blockable call returns `ARKRTOS_SYNC_ERR_WOULDBLOCK` and the App wrapper retries every 1 ms
  until the timeout.
- **Lifetime**: handles carry `ARKRTOS_SBUF_HANDLE_FLAG (0x01800000)`; `creator_id` records the
  creator, and when a task goes offline the objects it created are reclaimed (kernel-created objects
  with `creator_id=0` are not reclaimed).
- **Compile-time constraints**: `ARKRTOS_SBUF_BUF_SIZE < 16` or `ARKRTOS_MBUF_HDR_BYTES` outside 2..4
  is an immediate `#error`, not something discovered on the board.

7. **Real interrupt wake on board** (2026-11-13, a one-off temporary probe, **not committed**). The
   sender in item 6 runs in the timer daemon **task**, so `arkrtos_sync_in_handler()` takes the "not an
   interrupt" branch and the real ISR path had only code evidence. This time the probe was attached
   directly to the **SysTick hardware interrupt**:

   - a temporary block at the end of `SysTick_Handler()` in `board/stm32f427/arkrtos_board.c`
     (`#if (ARKRTOS_USE_SBUF == 1) && defined(ARK_UT_ISR_PROBE)`): if the global `g_ut_isr_sb >= 0`,
     call `arkrtos_sbuf_send_from_isr_internal()` with 4 bytes inside the interrupt;
   - a temporary case `sbuf_isr_wake_probe` in `kernelsrc/src/arkrtos_utest_cases.c`
     (`#if defined(ARK_UT_ISR_PROBE)`): create buffer → set `g_ut_isr_sb` → blocking read with 400 ms
     timeout → check content and elapsed;
   - once measured, both temporary edits were `git checkout` / deleted, **they are not in the commit**.

   Reading: `dt` measured with a deliberately failing assertion is **2 ticks = 1.0 ms** (SysTick is
   0.5 ms per tick, the interrupt sends and wakes immediately, wake latency within one tick period),
   the case run 3 times all PASS (6 assertions each). With the probe the whole set is
   `13 matched / 13 passed / 121 assertions`, probe profile `Code=226770` (the excess over 226302 in
   item 5 is the probe).

   So the "woken by an ISR" branch in `arkrtos_sbuf_recv_internal()` now has a real-hardware reading.
   Two qualifiers: the probe was a **one-off experiment** (no code kept), and it verifies `sbuf`; the
   same `arkrtos_sync_in_handler()` fork in `mbuf` / `mq` / `event` has not been verified separately.

   **A Keil project-file trap hit on the way**: adding `ARKRTOS_USE_SBUF=1` to the uvprojx `<Define>`
   box **has no effect even on a full rebuild** (`Code` stayed 220094 and the symbol was 0 in the map;
   `-r` rebuilds twice gave the same); putting it into `<MiscControls>` as
   `-DARKRTOS_USE_SBUF=1` did reach the compiler. From now on, to enable a switch temporarily in these
   projects use the `-D` in MiscControls, do not rely on the Define box — **and verify by looking for
   the symbol in the map, not by whether `Code` changed** (that time `Code` unchanged was precisely
   because it had not been compiled in).

## 6. Comparison with others

| | FreeRTOS | Zephyr | Ark RTOS |
|---|---|---|---|
| stream buffer | `xStreamBufferSend` (partial-success semantics, which this implementation follows) | `k_pipe` (with partial `k_pipe_get`) | `arkrtos_sbuf_send/recv` |
| message buffer | none built in (often queue + variable-size copy) | `k_fifo` / `k_msgq` | `arkrtos_mbuf_*` (length-header framing, whole message atomic) |
| trigger level (wake the reader only when nearly full) | yes (`xTriggerLevelBytes`) | no direct equivalent | **no, not provided**: currently "wake as soon as there is data"; a level threshold is an addable item and is not written into the capability table since it is not done |

## 7. Unprivileged channel on board (SVC 0x1F)

Everything verified above are **kernel-mode** calls (the cases run in the shell task). The App side goes
through SVC 0x1F, verified separately by the example
[`example/stm32f427/app_sdk/SBUF_DEMO`](../example/stm32f427/app_sdk/SBUF_DEMO/README.md): a `.svcapp`
creates, sends/receives, resets and deletes in its own unprivileged task, printing 33 criteria.

On-board result (STM32F427 + DAPLink, 2026-11-13):

```
SBUF: 33 pass, 0 fail
SBUF: ALL PASS
```

Covered: creation and initial capacity, stream semantics (partial read/write + order), empty read
returns `-2`, full write refused, `reset` returns capacity, byte order still sequential after wrap,
whole-message atomicity, no bleed after `TOO_SMALL`, length 0 / negative / null pointer refused without
changing the buffer, **blocking timeout**, invalid after delete. When the kernel does **not** have the
feature compiled in, SVC 0x1F truthfully returns -1 and the example FAILs rather than pretending
success.

**The App-side "blocking" is a 1 ms poll, not a real yield**: App tasks have no SVC channel to
create/yield tasks, so the oslib wrapper retries every 1 ms after the kernel returns `WOULDBLOCK`. So
what it can measure here is "was the timeout honoured": empty read with a 100 ms timeout, then a full
write followed by a 50 ms timeout, measured with `arkrtos_get_time_ms()` as **exactly 100 / 50 ms**
(neither early nor stuck). The boundary of this reading must be stated: 1 ms granularity is enough for
millisecond timeouts, but it is **not** "wakes within 1 ms of data arriving" — waking relies on the
next poll (only the kernel-side `sbuf_block_wake_contract` measures the wake latency after a real
yield).

Three easily misread measurement points (details in the example README):

- `create` returning `25165824` = `0x01800000` (object class and index encoded in the handle) is a
  handle, not an error code;
- the App side cannot see the `ARKRTOS_SBUF_ERR_*` enumeration (only in
  `kernelsrc/include/arkrtos_sbuf.h`) and can judge only by sign; `-2` / `-6` are the measured values;
- "the App passing a Flash address should be refused" is wrong: the App's own constant area is a legal
  source buffer and `send()` measured returns 4. The real refusal surface is length 0 / negative / null
  pointer.
