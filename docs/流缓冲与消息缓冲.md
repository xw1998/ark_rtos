# 流缓冲与消息缓冲（`arkrtos_sbuf` / `arkrtos_mbuf`）

一句话：**一块静态缓冲，两种用法**——按字节流收发（能收半条），或按带长度头
的消息收发（整条原子）。默认**关**（`ARKRTOS_USE_SBUF=0`）。

- 内核实现：`kernelsrc/src/arkrtos_sbuf.c`（整个文件被 `#if (ARKRTOS_USE_SBUF == 1)` 包住）
- 内核内部头：`kernelsrc/include/arkrtos_sbuf.h`
- 公开 API：`kernelsrc/include/arkrtos.h` 的 `@defgroup sbuf`
- App 侧封装（走 SVC）：`kernelsrc/sdk/app_sdk/arkrtos_oslib.c`
- 宿主回归：`kernelsrc/tests/test_sbuf_host.c` + `tools/sbuf_host_gate.py`
- 板端用例：`kernelsrc/src/arkrtos_utest_cases.c` 的 `sbuf_stream_contract`、`mbuf_framing_contract`
  （两个用例整段在 `#if (ARKRTOS_USE_SBUF == 1)` 里：开关关着时板端用例表里就没有它们）

---

## 一、两种语义，不要混用

| | 流缓冲 `arkrtos_sbuf_*` | 消息缓冲 `arkrtos_mbuf_*` |
|---|---|---|
| 单位 | 字节 | 一条消息（4 字节长度头 + 载荷，长度头宽度由 `ARKRTOS_MBUF_HDR_BYTES` 定） |
| 发送 | **可以部分成功**：空间不够时能写多少写多少，返回实际字节数 | **整条原子**：要么整条进，要么一个字节都不进 |
| 接收 | 读到多少算多少 | 一条一条读；缓冲太小则**整条丢弃**并返回 `ARKRTOS_SBUF_ERR_TOO_SMALL` |
| 典型场景 | ISR 往里塞字节、任务批量取走（串口/UART 收包） | 定界消息（命令、事件、一帧协议数据） |

> **同一块缓冲不要混用两套 API**。消息靠长度头定界，掺进裸字节流之后长度头就
> 错位了，此后每一次 `mbuf_recv` 读到的"长度"都是载荷里的某个字节。这不是
> 防御性唠叨，是这套实现唯一的用法约束。

## 二、接口

| 接口 | 说明 |
|---|---|
| `int32 arkrtos_sbuf_create(char *name)` | 创建（name 最长 7 字节）。静态对象表，失败返回负值 |
| `int32 arkrtos_sbuf_send(h, buf, len, timeout_ms)` | 写字节流，返回**实际写入**字节数；`timeout_ms` 0=不等待，负值=永久等待 |
| `int32 arkrtos_sbuf_recv(h, buf, len, timeout_ms)` | 读字节流，返回实际读出字节数 |
| `int32 arkrtos_sbuf_send_from_isr(h, buf, len)` | 中断里写，不阻塞，满了返回负值 |
| `int32 arkrtos_sbuf_used(h)` / `arkrtos_sbuf_free(h)` | 已存 / 剩余字节数 |
| `int32 arkrtos_sbuf_reset(h)` | 清空（并唤醒等空间的写者） |
| `int32 arkrtos_sbuf_delete(h)` | 删除（等待者收到"对象已删除"，不会睡到超时） |
| `int32 arkrtos_mbuf_send(h, buf, len, timeout_ms)` | 发一条消息，0=整条写入 |
| `int32 arkrtos_mbuf_recv(h, buf, len, timeout_ms)` | 收一条消息，返回消息长度 |
| `int32 arkrtos_mbuf_send_from_isr(h, buf, len)` | 中断里发一条消息 |
| `int32 arkrtos_mbuf_peek_len(h)` | 下一条完整消息的长度（没有则负值），可先问长度再准备缓冲 |

返回码：`ARKRTOS_SBUF_OK 0`、`ARKRTOS_SBUF_ERR_PARAM -1`、`ARKRTOS_SBUF_ERR_TIMEOUT -2`、
`ARKRTOS_SBUF_ERR_DELETED -3`、`ARKRTOS_SBUF_ERR_NOSPC -5`、`ARKRTOS_SBUF_ERR_TOO_SMALL -6`。

**为什么刻意跳过 -4**：`ARKRTOS_SYNC_ERR_WOULDBLOCK (-4)` 是用户态包装内部
"还得再等等"的信号。若把 NOSPC 也编码成 -4，App 侧的轮询包装会把它当成
"继续等"，于是"这一条根本放不下"变成"永远等下去"。

**为什么 `recv` 太小要整条丢弃**：留半条在缓冲里，下一次 `recv` 会把载荷的前
几个字节当成长度头读，整条流从此永久错位。丢一条消息是坏消息，读出一堆错
长度是坏系统。

**为什么 `send` 超过整块缓冲直接 NOSPC**：比整块缓冲还大的写入，等多久都放
不下，超时语义在这里没有意义。

## 三、配置

```c
/* kernelsrc/include/arkrtos_config.h */
#define ARKRTOS_SBUF_NUM       (4)     /* 对象个数 */
#define ARKRTOS_SBUF_BUF_SIZE  (256)   /* 每块缓冲字节数 */
#define ARKRTOS_MBUF_HDR_BYTES (4)     /* 消息长度头宽度，2..4 */
```

```c
/* kernelsrc/include/arkrtos_features.h，默认 0 */
#define ARKRTOS_USE_SBUF 0
```

Kconfig 同名符号 `ARKRTOS_USE_SBUF`（`config/kconfig/Kconfig.features`），
`tools/kconfig/genconfig.py` 生成到 `arkrtos_autoconf.h`。

关档代价：`arkrtos_sbuf.c` 编出**空目标**（实测 `text 0 / data 0 / bss 0`），
SVC 0x1F 一律返回 -1，镜像与命令表逐字节不变。

## 四、实现约定

- **环形区**：`rd`/`wt` 单调索引 + 手工回绕（缓冲大小不必是 2 的幂，不能用位与），
  以 `count` 判空/满——满的时候 `wt` 可以等于 `rd`，`count == size` 仍然正确。
- **阻塞/唤醒**：与 `arkrtos_mq` 同一套。状态变更全在关中断临界区内；没空间/没数据
  时先把当前任务登记进等待表，再**在同一个临界区里**调
  `arkrtos_task_block_in_critical()`（先挂表后睡，否则 ISR 的唤醒会投给一个还没
  睡下的任务 = 唤醒丢失）。被唤醒不等于拿到资源，醒来后按剩余超时重查重睡。
- **用户态**：走 `ARKRTOS_SVC_SBUF_CTRL (0x1F)`，参数块 24 字节，子命令 1..12。
  不可阻塞的返回 `ARKRTOS_SYNC_ERR_WOULDBLOCK`，App 包装以 1ms 轮询重试直至超时。
- **生命周期**：句柄带 `ARKRTOS_SBUF_HANDLE_FLAG (0x01800000)`；`creator_id` 记录
  创建者，任务下线时回收自己创建的对象（内核自建 `creator_id=0` 不回收）。
- **编译期约束**：`ARKRTOS_SBUF_BUF_SIZE < 16` 或 `ARKRTOS_MBUF_HDR_BYTES` 不在
  2..4 之间直接 `#error`，不留到板上才发现。

## 五、证据（分档，不混写）

**已验证**

1. 宿主单元测试 11 组断言全过（`python tools/sbuf_host_gate.py` → `SBUF-HOST OK`）：
   创建与初始状态、基本读写、空读超时、写满 + 部分成功 + 回绕顺序、超大写入
   NOSPC、reset、消息整条收发 + `peek_len`、TOO_SMALL 后不串下一条、超大消息
   NOSPC、delete、参数检查。`ci_gate` 新增 `sbuf-host` 门禁（现 14 项全绿）。
2. `arm-none-eabi-gcc -fsyntax-only`：`arkrtos_sbuf.c` / `arkrtos_task.c` /
   `arkrtos_init.c` / `arkrtos_oslib.c` / `arkrtos_utest_cases.c` 在开关开、关两档
   均通过（只剩 `arkrtos_app_image.h` 的既有 `variably modified` 警告）。
3. **真实链接**（H743 GCC 工程，`make USE_SBUF=1`）：
   FLASH 453788/512KB（86.55%）、RAM 444548/440KB（98.67%）；
   同工程关档 FLASH 445996、RAM 443300 ⇒ **开档 +7792 B FLASH / +1248 B RAM**。
4. **F427 GCC 工程开档链接失败**（如实记账）：关档已占 FLASH 257324/262144
   （98.16%，余 4820 B），本模块目标文件 `text 4140 / bss 1264`，加上字符串后
   `ld` 报 `Relaxation not supported with --enable-non-contiguous-regions
   (section '.rodata.str1.4' would overflow '.rodata' after it changed size)`。
   ⇒ F427 演示工程**当前塞不进**这个模块，要开就得先腾 FLASH（例如关掉某个
   组件或缩减缓冲）；这不是模块缺陷，是那个工程本来只剩 4.8 KB。
5. **F427 Keil 工程开档上板**（2026-11-13，DAPLink 已接）。把 `ARKRTOS_USE_SBUF=1`
   临时加进 `example/stm32f427/kernel/ARKRTOS_TEST/MDK-ARM/ARKRTOS_TEST.uvprojx`
   的 Define 框（**源码头仍默认 0**，与 tickless 那次的做法一致），`0 Error 0 Warning`：
   `Code=225478 RO-data=19830 RW-data=896 ZI-data=122116`。宏撤掉后重建默认档
   `Code=220094 RO-data=19198 RW-data=896 ZI-data=120852` ⇒ 开档
   **+5384 B Code / +632 RO / +1264 ZI**。这个 +5384 与上面 H743 GCC 的 +7792
   **不可互引**（编译器、工程、被链进的东西都不同）。
   板上 `utest` 的逐字输出：

   ```
   RUN   sbuf_stream_contract
   PASS  sbuf_stream_contract
   RUN   mbuf_framing_contract
   PASS  mbuf_framing_contract
   utest: 11 matched, 11 passed, 0 failed, 0 skipped; assertions 104 run / 0 failed
   ```

   同一块板上默认档是 `9 matched, 9 passed ... assertions 73 run / 0 failed`，
   差的正是这两个用例的 31 条断言。这条读数的意思只有一个：**非阻塞语义在真机上成立**
   （回绕、部分成功、整条原子、`TOO_SMALL` 之后不串下一条），不是"编过"。
   顺带删掉 `arkrtos_sbuf_send_internal()` 里一个声明了从未使用的 `written`
   （开档时 AC6 报 `#177-D`）；默认档 `Code` 前后都是 220094，逐字未变。

**未验证**

- **阻塞/唤醒在真机上的行为**：宿主测试里 `arkrtos_task_get_current()` 返回 0、
  `arkrtos_task_block_in_critical()` 返回 -1，所以宿主只覆盖非阻塞路径。板上跑的
  那两个用例也全是 `timeout_ms=0`（用例在 shell 任务里跑，绝不能把控制台挂住）。
  ⇒ **唤醒、超时重睡、ISR 唤醒不丢这三条仍然没有真机读数**。原因是缺一个"第二
  个任务"：App 侧没有创建任务的 SVC（`0x11` 的 task_ctrl 只有 wait / kill / delay），
  要验它得在核内起一个任务 + 一个定时器回调（一次板端实验，不是用例）。**没做就不写"验过"。**
- **SVC 通道**：用户态封装（`ARKRTOS_SVC_DECL_1(int32, 0x1F, arkrtos_call_sbuf_ctrl, ...)`）
  仍只有编译证据；F427 板上**没有**从非特权态发起过 sbuf 调用。
- **F401**：只有 Keil 工程，本轮没有对应 GCC 工程可做体积对比。

## 六、和别家对照

| | FreeRTOS | Zephyr | Ark RTOS |
|---|---|---|---|
| 流缓冲 | `xStreamBufferSend`（部分成功语义，本实现与之对齐） | `k_pipe`（有 `k_pipe_get` 的部分读） | `arkrtos_sbuf_send/recv` |
| 消息缓冲 | 无内建（常用 queue + 变长拷贝） | `k_fifo` / `k_msgq` | `arkrtos_mbuf_*`（长度头定界，整条原子） |
| 触发水位（几乎满才唤醒读者） | ✓（`xTriggerLevelBytes`） | 无直接对应 | **✗ 暂不提供**：当前是"有数据就唤醒"，水位阈值属可加项，没做就不写在能力表里 |
