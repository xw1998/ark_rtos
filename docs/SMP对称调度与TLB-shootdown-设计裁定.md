# SMP 对称调度与 TLB shootdown：设计裁定

> 状态：**裁定完成，不实现**（2026-11-23）。
> 本页回答的是「为什么不做、什么条件下才该重开」，不是操作手册。
> 载体级别：**纯文字裁定**，输入只有两类——既有 QEMU 实跑读数（引用页码）与只读源码核验（核对命令在本页给出）。
> 本页不产生新读数，也不改变任何代码行为。

## 0. 三句话结论

1. 内核现在停在 **AMP（非对称多处理）**：每个次核都有自己的运行队列、时间片与切换路径，
   但只有 CPU0 是「内核核」——次核不发 SVC、不调内核 API、不推进全局 tick。
2. **TLB shootdown 不实现。** 它要服务的前提是「用户态任务在两个核上并发访问同一虚拟地址」，
   这个前提在本内核里不存在。前提不存在时实现它，写出来的只会是一个「发了 IPI 就假定已失效」的函数，
   而那种函数在真机上比没有更危险。
3. **对称调度同样不做。** 它要改的是「内核核」这个架构前提本身（每核独立内核栈 / 中断路径 /
   SVC 分派 / 共享就绪结构），改动量与可验证性都不成比例。重开条件写在 §5.3，逐条可机械核对。

## 1. 三个台阶，本内核站在第一级

| 台阶 | 含义 | 本内核 |
|---|---|---|
| **AMP 策略分核** | 每核各有运行队列与切换路径；任务由 CPU0 显式迁出/要回；次核不进入内核 | **是**（④ 2026-11-19 手工迁移、⑤ 2026-11-23 自动均衡） |
| **对称调度** | 任一核都能从同一结构取任务并运行任意任务，调度决策不绑定某个核 | 否 |
| **完整 SMP** | 对称调度 + 内核可被任一核进入（SVC / 异常 / 锁）+ 跨核一致性协议（含 TLB） | 否 |

现状的四条边界不是「临时状态」，是写进头文件的设计约束：

- **次核不许发 SVC、不许调内核 API**：`la_smp_trap_c` 遇 SYS 一律致命停机，不静默放行。
  这不是保守，是因为次核没有内核栈、没有全局锁保护、也没有被内核异常路径覆盖。
- **只接受 READY 任务迁移**：RUNNING 要先把帧让出来，WAIT/DELAY 的等待语义挂在全局结构上，搬走就是错的。
  拒绝码 -3；⑤ 又加了 -6（正在 CPU0 上跑的任务不迁，否则两核共用一份栈帧）。
- **次核节拍不推进全局 tick**：每核 TCFG/TVAL 是独立的，`arkrtos_kernel_tick` 只由 CPU0 推进。
- **迁移是「请求 + 每拍轮询」**：`task_to` / `task_back` 只登记，真正生效由次核在切换点收走，延迟上限 1 拍。

⑤ 的自动均衡是在这一层之上加策略（往哪边挪、什么时候挪回去），**没有改动这四条中的任何一条**。

## 2. 直接做对称调度要付什么

按依赖顺序拆，每一条单独都不小：

1. **全局时钟同步。** 现在每核一个 timer，全局 tick 只有 CPU0 推进；对称调度的第一步就得让「时间」在核间
   有一致定义（选一个主时钟源 + 漂移处理，或者每核计本地 tick、只在需要时用全局号）。
2. **次核进内核。** 需要：每核独立内核栈、每核中断入口的完整保存/恢复、SVC 分派表在次核上下文里可用、
   以及内核临界区在「同时有两个核在里面」时仍然成立。当前 `eentry` 已经按 `CSR.TID` 分流，
   但次核那一路只做到「进 trap → 认号 → 不认识的直接致命」，没有内核调用面。
3. **调度结构。** 现在是「全局单就绪链 + 每核队列影子 + `owned_by_other()` 跳过」，这是为 AMP 设计的。
   对称调度要求每核从共享结构独立取任务，`ready_rebuild` / `sched_check` / 线性优选三处都得改写。
4. **锁与内存序。** 现在每核一把自旋锁保护自己的队列，临界区只有几条数组操作。
   对称调度会把内核算术放进多核并发路径，跨核内存序从「只有迁移交接点需关心」变成「处处需关心」。
5. **验证成本。** 本机最强载体是 QEMU（LA64 `-smp 2`，MTTCG）。它能证明「两个核都在跑、都收到了 IPI、
   队列状态对得上」，但**不能证明**真机上的竞态与 TLB 一致性协议行为。这一步的结论只能靠真板。

一句总账：这五条里任何一条的验证量，都不小于 ④+⑤ 两轮的总和。

## 3. TLB shootdown：这个 QEMU 上能怎么做

U-7b 的取证（[QEMU模拟器移植与验证](QEMU模拟器移植与验证.md) §5.28 / §5.29）结论是硬的：

| `invtlb` op | 本 QEMU 上的行为 |
|---|---|
| 0 / 1 / 2 / 6 | 整表清空，随后内核 refill 直接 `KERNEL ... fatal` |
| 4 / 5 | 空操作（不报错、也不失效） |
| 7 | 非法指令 |
| 3 | 按 VA 失效，**不看 ASID** |

也就是说：**这个载体上没有「按 ASID 定向失效」这条指令**。就算前置齐了，shootdown 也只能做成
「唤醒目标核，让它自己按 VA 失效」，而不是广播式刷表。这一点决定了实现形态的上限，也决定了它的成本。

## 4. 三条前置，一条都没到位

1. `arkrtos_port_send_ipi()` **明确拒绝核 0**。源码原句：
   「核 0 是引导核：本移植没有给主核装 IPI 处理路径（它一进异常就落到 `la_trap_c` 的通用链路），
   所以拒绝自投，明确报 -1」。⇒ 次核无法让主核失效条目。
2. 次核入口 `arkrtos_smp_secondary_entry` **从不打开分页**（不写 `CRMD.PG`、不建 TLB），保持复位态直通。
   ⇒ 次核自己根本没有 TLB 条目可以「陈旧」。
3. **不存在「用户态任务在两个核上并发访问同一 VA」这个前提**。次核的 trap 分派对 SYS 一律致命停机；
   `arkrtos_smp_sched_task_to()` 虽然不拒绝 PLV3 任务，但全仓只有演示调用者。

核对命令（三条都能机械跑）：

```bash
grep -n "send_ipi" -A 12 kernelsrc/port/loongarch/la64/arkrtos_port.c
awk '/arkrtos_smp_secondary_entry/,/arkrtos_smp_secondary_main/' \
    kernelsrc/port/loongarch/la64/arkrtos_context.S
grep -rn "arkrtos_smp_sched_task_to" kernelsrc/ example/
```

判据 = 第一条不再返回 -1；第二条出现写 `CRMD.PG` 的语句；第三条出现非演示调用者。

## 5. 裁定

### 5.1 保持 AMP，并把它说清楚

对外只允许这样描述：「SMP 支持 = 双核并行 + 显式/自动任务迁移，次核为纯计算核」。
**不允许**写成「对称多核」「负载均衡 SMP」「完整 SMP 支持」——那会让人以为任一核都能进内核。

### 5.2 TLB shootdown 不实现，也不做看起来能用的替代

明确拒绝以下三种「假实现」：

- 发一个 IPI，然后**假定**目标核已经失效（没有任何回执判定）；
- 在 `invtlb` op 4/5 上包装一层，声称「按 ASID 失效」（本载体上是空操作）；
- 用整表清空代替定向失效，然后宣称「一致性已保证」（会把自己内核的 refill 打成 fatal）。

现有做法（`space_release` 保留「切 ASID → 按 VA 撤 → 切回 → 补铺」）就是在没有 shootdown 时的
正确形状：**每个核只改自己看得到的映射，跨核共享只发生在迁移交接点。**

### 5.3 重开条件（全部满足才重开，缺一条都不算）

| # | 条件 | 判据 |
|---|---|---|
| R1 | 主核有 IPI 处理路径 | `arkrtos_port_send_ipi(0)` 返回 0，且主核 trap 表里有一条登记给该向量的处理函数 |
| R2 | 次核开分页 | 次核入口出现写 `CRMD.PG` 的语句，且次核能自己建/查到 TLB 条目（有读数） |
| R3 | 存在真实的跨核共享 VA 调用者 | 至少一处非演示调用：用户态任务经 `task_to` 到次核，且两核都会访问同一窗口 VA |
| R4 | 有回执判定手段 | 能证明「目标核确实失效了」，不是靠时间等待（真机或 QEMU 上的可读计数） |
| R5 | 有真机载体 | 竞态与一致性协议行为不能只在 QEMU 上判死 |

R1–R4 都可以在本机推进（前三项是代码，第四项要设计一个可读的失效回执）。**R5 只能靠真板**，
所以在没有板子的阶段，shootdown 最多做到「QEMU 上能演示」，不能宣布「已支持」。

### 5.4 若重开，最小第一步

顺序是死的，不能跳：

1. 先做 R1（主核 IPI 路径）——它是唯一一个「不改分页、不改调度」的独立增量，可以先单独交付并压测；
2. 再做 R2（次核开分页）——此时次核才有可失效的条目；
3. 最后才谈失效协议：目标核收到 IPI → 在安全点按 VA 失效 → 回写一个可读计数 → 发起核等到计数变化。
   等待必须有上限且失败要**如实报错**，不允许「超时即认为成功」。

### 5.5 代价估算（量级，不给假精度）

| 改动点 | 量级 | 依据 |
|---|---|---|
| 主核 IPI 路径（R1） | 一条 trap 分支 + 一个处理函数 + 门禁 | 次核侧同类路径已有，可对照 |
| 次核开分页（R2） | 次核启动序列 + 自己的映射安装 + 读数 | 主核分页已完整（U-3/U-5/U-7/U-16），可复用 |
| 失效协议（R3/R4） | 新模块 + 调用点插入 + 真机验证 | 无本机先例，风险最高 |
| 完整对称调度 | 重写时钟 / 就绪结构 / 锁 / 中断面 | 见 §2 五条 |

## 7. 边界与未验证

- `invtlb` op 的语义是**本 QEMU 载体**的行为；真机手册上的定向失效是否存在，本机无从验证。
  因此 §3 的结论只在「以 QEMU 为验证载体」的范围内成立。
- 「次核不进入内核」是当前实现的**有意**约束，不是遗漏；改它属于架构级改动，需先有新预注册。
- 本页没有新增实验，也就没有新增「已验证」条目。第 5 节的裁定是**取舍**，不是性能结论。
