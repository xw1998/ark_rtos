# Ark RTOS 已知限制

这份是**唯一一页"限制清单"**。此前这些限制散在 `与Linux差距盘点`、`小程序设计`、
`安全认证准备`、`lwIP协议栈接入`、`软总线接入`、`实时性与最坏延迟` 各篇里，读者
要拼起来才知道边界在哪。每条都注明"是取舍还是欠账"，以及证据在哪。

> 分档口径：**取舍** = 定位上不做，写进文档是让人别指望；**欠账** = 该做没做完或
> 没验证，`docs/欠账盘点.md` 里有对应条目。

## 一、执行模型

| 限制 | 性质 | 说明与证据 |
|---|---|---|
| 没有 MMU，没有进程/虚拟地址空间 | 取舍 | App 在分区内固定 RAM 窗口里跑，每个任务是**同一个地址空间**加逐任务 MPU 窗口。`fork`/`execve`/按需分页/swap 一概没有。见 [与Linux差距盘点](与Linux差距盘点.md) |
| MPU 是区域级，不是页级 | 取舍（硬件决定） | Cortex-M 的 MPU 只有 8 个 region、最小 32 B 粒度，且必须 2 的幂对齐；"一页 4 KB 保护"这种粒度做不到。App 越权验证见 [内存保护与App越权验证](内存保护与App越权验证.md) |
| 单核，无 SMP | 取舍 | 调度器是单核就绪集；没有 per-CPU 结构、没有核间同步。见 [与成熟RTOS对比](与成熟RTOS对比.md) 的"定位差" |
| 用户态等待是"登记 + 轮询"，不是内核阻塞 | 取舍（SVC 隔离的代价） | 非特权侧不能自己挂起，只能登记后由内核在派发点 peek。语义上等价，代价上多一层轮询。见 [同步原语与令牌守恒](同步原语与令牌守恒.md) |
| 支持的核：Cortex-M3 / M4 / M7 | 欠账（范围外） | 没有 M0/M0+/M23/M33 移植，也没有 TrustZone（SAU/安全世界）。上 M33 要新写 port 与 SVC 重定向 |

## 二、应用形态

| 限制 | 性质 | 说明与证据 |
|---|---|---|
| 三种应用：`.svcapp`（app/driver）、裸镜像、小程序 | 设计决定 | 都不是 ELF：没有动态链接、没有符号表加载、没有共享库。App 的入口与 SVC 面是固定 ABI（见 [API参考](api/Ark%20RTOS_API参考.md)、`arkrtos_app_image.h`） |
| 小程序有数量与体积上限 | 取舍 | 并发数 `ARKRTOS_MINI_MAX` 默认 2（1..4，超范围 `#error`）；体积上限受装载窗口约束。见 [小程序设计](小程序设计.md) |
| 小程序崩溃后跨复位禁用 | 设计决定 | 崩溃计数落盘，达到上限后不再自启，要人工/上位机卸载重装；没有自动回滚 |
| C++ 基本不可用 | 欠账 | 目前只有 `arkrtos_app_image.h`、`arkrtos_blk.h`、`arkrtos_fs.h` 三个头带 `extern "C"`；没有全局构造器调用表、没有异常支持 |

## 三、系统服务

| 限制 | 性质 | 说明与证据 |
|---|---|---|
| POSIX 是子集 | 取舍 | 有 pthread / mutex / sem / 时间 / socket / select；没有 signal、fork、文件锁、`mmap`、进程组。见 [POSIX与Windows兼容层说明](POSIX与Windows兼容层说明.md) |
| VFS 没有 Unix 权限模型 | 取舍 | 没有属主/权限位/`chmod`；访问控制靠"谁能调到哪个 SVC"。见 [VFS路径命名空间](VFS路径命名空间.md) |
| 文件系统是 littlefs 单卷 + ramfs | 取舍 | 没有日志型 FS、没有多卷并发写、没有配额 |
| Shell 只有一路串口控制台 | 取舍 | 控制台独占 USART1，所以软总线拿不到物理串口（这是"两节点未验证"的直接原因） |
| 真实以太网未打通 | 欠账 | 板级没有 PHY 驱动、MDIO 读写、`eth_` 接口与 RMII 引脚分配，网络路径跑的是回环 netif。见 [lwIP协议栈接入](lwIP协议栈接入.md) §1 |
| 软总线只在板内 loopback 上验证过 | 欠账 | 两节点走真实串口线（两块板 / 板 + PC）未验证；MCU 档位还要工程侧自己给 `-DARK_BUS_*`。见 [软总线接入](软总线接入.md) §7 |

## 四、可靠性与安全

| 限制 | 性质 | 说明与证据 |
|---|---|---|
| 镜像签名是对称 HMAC，不是信任链 | 取舍（当前实现） | 32 字节密钥编进构建，**能签就能验**，没有非对称签名、没有证书链、没有密钥轮换。密钥绝不入库（`*_sign_key_local.h` 被 gitignore） |
| 签名只在安装期校验 | 取舍 | 运行期不重校验镜像；已经在跑的镜像被改不会被发现（要靠 MPU 与崩溃账本兜） |
| 版本闸门在签名闸门之前 | 设计决定 | 版本不递增时先被 `INSTALL:211` 挡住，走不到 `LOADER:1046` 的验签 |
| 不做差分 OTA / A/B 回滚 | 取舍 | 升级是"装新镜像 + 交接控制权"，出错靠崩溃上限与人工卸载，没有自动回滚 |
| 热切换要求新旧版本**布局全等** | 设计决定 | `ARKRTOS_USE_TASK_SWAP` 整块搬运 RAM / 换 Flash 槽，所以块大小、槽类型、RAM 大小必须逐项相等（`ARKRTOS_SWAP_ERR_LAYOUT`），否则拒绝。布局会变的升级只能走 [无缝升级例程](无缝升级例程.md) 的交接协议 |
| 热切换**会重置数据段** | 实测修正 | 整块搬运确实搬了旧块内容，但镜像入口是启动桩（`__main` / `MINISTART`），落地后重跑 `.data` 初值搬运与 `.bss` 清零，探针实测 `bss` 与 `data` 都回到初值（[详情](无缝升级-双缓冲热切换.md) §5）。所以跨版本状态仍须自己序列化，而不是依赖内存连续 |
| 用过 FPU 的任务不支持热切换 | 欠账 | 扩展异常帧的 `[7]` 是 S6 不是 xPSR，按基本帧改写会写坏现场，故直接拒（`ARKRTOS_SWAP_ERR_FRAME`）。要支持须整块搬 S0–S31 |
| 热切换只在 STM32F427 上上板验证 | 覆盖边界 | 旧块还池、旧槽保留 `LOADED`、反向切回、切换 58~233 ms 四条都是 F427 + DAPLink 的读数；M3/M7 与其它板卡未测。见 [无缝升级-双缓冲热切换](无缝升级-双缓冲热切换.md) §9 |
| 热切换落地可能违约一次心跳契约 | 已知限制 | 四次切换里观测到一次 `GUARD ... violating 1`（`crash` 记 `slot 0 faults=1 last=heartbeat`）：新镜像在新契约注册之前的那一拍没喂狗。契约不随切换结转，修法未做。见 [无缝升级-双缓冲热切换](无缝升级-双缓冲热切换.md) §9.2 与 §10 |
| 热切换没有自动回滚编排 | 欠账 | `app swap` 保留旧槽只是回滚的原材料；「换了之后 N 秒没心跳就切回去」需要先定「谁判定新版本失败」，未做。见 [无缝升级-双缓冲热切换](无缝升级-双缓冲热切换.md) §10 |
| 热切换一次只允许一份在途 | 设计决定 | 内核只有一个挂起槽，第二个 `mini swap` / `app swap` 返回 `BUSY`；多实例升级要排队 |
| 崩溃上限 3 次即禁用，需人工恢复 | 设计决定 | 见 [崩溃恢复与镜像版本把关](崩溃恢复与镜像版本把关.md) §1.7 |
| 实时性不是硬实时认证口径 | 欠账（口径） | `rt` 给的是 DWT 周期计数的实测值（tick.isr / wake.lo / wake.hi / crit.max），没有 WCET 分析、没有最坏执行时间证明。见 [实时性与最坏延迟](实时性与最坏延迟.md) |
| tickless 只在 F427 上板、电流未测 | 现状 | 板端已实测：`rt` 报 `isr=18605 sleeps=18682 skipped=48728 of 67333 tick(s)`，中断降到 27.6%，静置 20 s 不丢拍；**但功耗没有电流表读数**，只有"睡得更久"这一条间接证据。见 [低功耗与 tickless](低功耗与tickless.md) §8 |
| 安全认证未送审 | 现状 | `sec` 的 T1–T12 是**本地用例自测**，不等于任何一张证书；`docs/安全认证准备.md` 是差距表与缺口寄存器，不是合规声明 |
| shell 认证缺失、Flash 选项字节只能读不能设 | 欠账 | shell 认证 = SEC-G13；选项字节**读取**已做（2026-11-13，`sec` 的 `flash.protection` 报真实 RDP/WRP），**设置**（RDP/WRP 写入，不可逆、需产线）= SEC-G04 的另一半。见 [安全认证准备](安全认证准备.md) §7 |

## 五、开发与工具链

| 限制 | 性质 | 说明与证据 |
|---|---|---|
| 只能真板调试，无仿真/gdb stub | 欠账 | 没有 QEMU/Renode 目标，也没有 gdb remote stub；调试走 Keil UV4 + pyocd + `mdkdebug` MCP |
| 源码编码混用 | 现状约束 | 旧源 GBK、新增 UTF-8，`ci_gate` 的 `encoding` 只保证"每个文件各自可解码"，不保证统一；改 GBK 文件要**字节级补丁**，整文件转码会让 diff 变成全文重写 |
| GCC 例程依赖外部工具链 | 现状 | `GCC构建指南` 里那套需要 `arm-none-eabi-gcc`；仓库不自带，本机不一定装了（构建状态见该指南的"验证状态"） |
| `pyocd` 读数不能当证据 | 现状约束 | 目标**运行中** `read32` 外设返回常量假值（`RCC_CR` / `FLASH_OPTCR` / `GPIOC_ODR` 同一地址族全给 `0x03000000`），必须 `halt` 才是真值；而 `halt → read → go` 实测会把目标复位（看门狗）：`hwsafe` 的 `handover` 归 0、`tick.isr` 从头计数。瞬时状态只能靠 shell 读内核自己的计数，见 [小程序设计](小程序设计.md) §9.6 |
| 无静态分析与覆盖率基线 | 欠账 | 仓库里没有 cppcheck / MISRA / clang-tidy / gcov 配置；宿主测试 11 个（`kernelsrc/tests/test_*_host.c` 9 个 + SDK 2 个）、板端 `utest` 9 例，对 828 个内核函数来说覆盖率近乎零 |

## 六、怎么用这页

* 写代码前想知道"这件事能不能做" → 查上面四张表。
* 想知道"什么时候能补上" → 看 [欠账盘点](欠账盘点.md)，那里每条都有核对命令与优先级。
* 发现这页漏了限制 → 直接补进来并注明证据，不要另起一页（另起一页就又散了）。
