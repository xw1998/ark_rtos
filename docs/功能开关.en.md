# Feature Switches

**[简体中文](功能开关.md) | English**

> Condensed English edition. The Chinese page (功能开关.md) is normative: every
> number below is copied from it as of 2026-11-18, but if the two disagree, the
> Chinese page wins. This page adds no new claim and no new measurement. Long
> measurement asides are abbreviated here; the Chinese page has the full text.

## In one sentence

Every kernel feature that "not every system needs" has a switch; the table lives in
`kernelsrc/include/arkrtos_features.h`. Switching one off does not make the build fail -
that feature ceases to exist, and **everything it says to the outside remains true**.

## How to use it

**Preferred: edit the Kconfig defconfig** (the only recommended path since 2026-11-14).

```bash
# default profile: edit config/arkrtos_defconfig (the source of the committed shared header)
py -3 tools/kconfig/genconfig.py --kconfig Kconfig \
    --defconfig config/arkrtos_defconfig \
    --out kernelsrc/include/arkrtos_autoconf.h

# GCC projects: edit config/<board>_defconfig, or use a knob
cd example/stm32h743/kernel/ARKRTOS_TEST/GCC && make USE_ARKVIM=0
```

**Project macros are now zeroed out** (neither Keil's `<Define>` nor GCC's
`-DARKRTOS_USE_*` carries feature switches any more), so the old trap "a project macro
beats Kconfig" is structurally impossible now.

Only two classes of macro remain, and neither is a feature switch:

* **board capability**: `ARKRTOS_USE_FPU` / `ARKRTOS_USE_LSX` / `ARKRTOS_USE_MPU` /
  `ARKRTOS_USE_PRIV`, plus
  `ARKRTOS_BOARD_CONFIG` (which board header);
* **build-time budget of upstream components**: `MDK_TRACE_*` / `LFS_NO_*` / `ARK_BUS_*` /
  `ARKVIM_*` / `ARKC_*` / `ARK_RAMFS_*`, plus the vendor SDK's `USE_HAL_DRIVER` /
  `STM32F4xx`.

Every entry in `arkrtos_features.h` is still `#ifndef / #define / #endif`, so a command
line `-D` can technically override it - but that is an **emergency measure**, not a
listed use: `tools/ci_gate.py` and code review both assume "the value comes from
Kconfig".

## Three layers of switches, do not mix them

| Layer | Governs | Where | Examples |
|---|---|---|---|
| Capability | what this **chip has** | board config `board/*/arkrtos_board_config.h` | `ARKRTOS_USE_FPU` / `ARKRTOS_USE_LSX` / `ARKRTOS_USE_MPU` / `ARKRTOS_USE_PRIV` |
| Optionality | what this **build wants** | Kconfig (`config/kconfig/` + defconfig), values land in the `#if`s of `arkrtos_features.h` | everything below |
| Resources | how much **this board has** | `config/<chip>/arkrtos_partition.h` | `SHELL_DEV_NAME` / `SHELL_TASK_STACK_SIZE` / `APP_TASK_PRIORITY` |

Capability states hardware facts, optionality states software choices, resources state
board budget - one switch belongs to exactly one layer.

**A capability-layer `ARKRTOS_USE_LSX` (default 0)**: whether LoongArch's 128-bit LSX
vector registers (`$vr0..$vr31`, 32 x 16 B) are saved per task. At 1 the trap frame
grows a 512-byte vector area after the FPR area (`528 + 16*i` holds `$vr{i}`, so the
frame is 528 -> **1040**) and `start.S` sets `EUEN.SXE`; at 0 not a single extra byte
is stored and that bit stays clear (touching `$vr` raises `Ecode=13 INE`, an explicit
fault instead of a silent wrong answer). It requires `ARKRTOS_USE_FPU=1` (the vector
area hangs off the FPR area; otherwise a hard `#error`). **LASX (`$xr0..$xr31`) is
not part of this profile**: `EUEN.ASXE` is deliberately left 0 - `xvst` needs 32-byte
alignment while the frame base only guarantees 16, and half-saving is worse than not
saving. The default profile is byte-identical (QEMU LA64, same sha256 with a fixed
`SOURCE_DATE_EPOCH` after `--strip-debug`: `3e6858e8...`); the on-profile QEMU readings
and the negative control are in
[QEMU模拟器移植与验证](QEMU模拟器移植与验证.md) §5.31 (Chinese page).

**The shell is a Kconfig symbol too** (`ARKRTOS_USE_SHELL`, since 2026-11-14). It used to
be `SHELL_ENABLE` in `config/arkrtos_partition.h`, which meant "invisible to Kconfig and
impossible to turn off from a defconfig". `arkrtos_features.h` now aliases it:

```c
#ifndef SHELL_ENABLE
#define SHELL_ENABLE  ARKRTOS_USE_SHELL
#endif
```

(The `#ifndef` guard keeps an emergency `-DSHELL_ENABLE=0` working.) The historical
definitions in the three `arkrtos_partition.h` files are gone; only board resource
constants remain.

## Switch list

### 1. Core mechanisms

| Switch | What disappears when off |
|---|---|
| `ARKRTOS_USE_SPINLOCK` | spinlocks degrade to a **pure interrupt-disable** implementation (enough on one core, no atomic CAS, no SMP reservation). Semantics stay; callers are unchanged |
| `ARKRTOS_USE_SCHED_LOCK` | **cannot be turned off** (0 is a hard `#error`). Lock semantics have no honest downgrade |
| `ARKRTOS_USE_STACK_USAGE` | per-task stack high-water accounting disappears; that `task` column prints `n/a`. The `stack` command **is still registered** but answers one line: `stack: accounting is compiled out (ARKRTOS_USE_STACK_USAGE=0) - no numbers to show` - no invented numbers |
| `ARKRTOS_USE_STACK_CHECK` | stack tail sentinel checks disappear |
| `ARKRTOS_USE_SCHED_STAT` | scheduling statistics zeroed (context switch counts etc.) |
| `ARKRTOS_USE_CPU_LOAD` | CPU load no longer queryable |
| `ARKRTOS_USE_FAST_TICK_SWITCH` | the "raise PendSV on demand" fast path goes away; every tick decides again |
| `ARKRTOS_USE_TICKLESS` | no tick merging when idle; back to one `WFI` per tick (woken every 500 us). Default off; `arkrtos_tickless.c` compiles to an empty object, tick handler and `ARKRTOS_WFI()` are the same code, **zero change in size and behaviour**. Bound `ARKRTOS_TICKLESS_MAX_TICKS` (default 8). F427 measured: on-profile `Code=220562` / `RO=19266` / `RW=920` / `ZI=120860`, i.e. **+648 / +68 / +24 / +8**; `rt` gains one line `tickless isr=... sleeps=... skipped=... of ... tick(s)` (compiled only when on), measured interrupt reduction to 27.6% |
| `ARKRTOS_USE_FAULT_RECOVER` | no attempt to recover scheduling after a fault |
| `ARKRTOS_USE_MPU_APPLY_CACHE` | the MPU context cache does not apply: every task switch rewrites all MPU registers (slower, semantics unchanged) |
| `ARKRTOS_USE_PAGING` | **a backend swap, not a feature off**: at 1, `arkrtos_paging.c` (page table / TLB + PLV) takes over the isolation contract and `arkrtos_mpu.c` becomes an empty object; at 0 the reverse. They are **mutually exclusive**; both at 1 is a hard `#error`. Default 0 (window backend) |
| `ARKRTOS_USE_PAGING_SWAP` | **the on-demand page replacement does not exist**: the whole evict/reload machinery in `arkrtos_port.c` (slot ledger, 8 slots x 8 KB swap area, 8 KB relay buffer) is not compiled; on a fault with an empty frame pool the original fatal path returning 0 stays; `arkrtos_paging_swap_stat()` becomes the identity macro `(0u)` and the `pmap swap` / `pmap swaptest` branches are not compiled. Default 0; requires `ARKRTOS_USE_PAGING` + `ARKRTOS_USE_PAGING_DEMAND` + `ARKRTOS_USE_PAGING_FRAMES` (otherwise `#error`). Slots `ARKRTOS_PAGING_SWAP_SLOTS` (1..64, default 8). The swap area is a kernel `.bss` array - **not a disk file, so it saves no memory**; this profile verifies ledger and copy correctness. Off profile byte-identical |
| `ARKRTOS_USE_PAGING_ASID` | **per-space ASIDs do not exist**: `la_asid_get`/`la_asid_swap`, the `la_pg_pair_check` readback and the `pmap asid` branch are not compiled, macros revert (`LA_PG_WIN_WAY_OF(s) -> LA_PG_WIN_WAY`, `LA_PG_ASID_OF(s) -> 0`, `LA_PG_DYN_G -> 0`), and a space switch stays "512 `invtlb` plus rewriting 256 entries". Default 0; requires `ARKRTOS_USE_PAGING` + `ARKRTOS_USE_PAGING_PAGES=1` + `ARKRTOS_USE_PRIV=1` and `ARKRTOS_PAGING_APPS_MAX <= 8` (one STLB way per space), otherwise `#error`. When on, space `s -> ASID s+1`, way `s % 8`; switching writes `CSR.ASID` once and reads back the first and last pair. The three read interfaces are **macros** when off, emitting no symbols. Off profile byte-identical (QEMU LA64: `6859ec53...` against the HEAD tree under the same criterion) |

### 2. Synchronisation and IPC

| Switch | What disappears when off |
|---|---|
| `ARKRTOS_USE_MEMPOOL` | no fixed-block pool: create fails, allocation returns 0, SVC 0x20 always returns -1 (callers find another way; nobody gets memory that will fragment) |
| `ARKRTOS_USE_MQ` | no message queues: create fails, send/receive refused (never a handle that silently drops messages) |
| `ARKRTOS_USE_TIMER` | no soft timers: create/start refused, callbacks are never promised |
| `ARKRTOS_USE_SBUF` | no stream/message buffers: `arkrtos_sbuf.c` is an empty object, SVC 0x1F returns -1. Default off (each buffer statically costs `ARKRTOS_SBUF_BUF_SIZE` x `ARKRTOS_SBUF_NUM`) |
| `ARKRTOS_USE_ESET` | no 32-bit event sets: `arkrtos_eset.c` is an empty object and the SVC 0x21 factor-set code is not compiled (the case is absent from the dispatch table, not "enterable but returning -1"). Default off; measured on F427 `Code=221854` (default `220290`, **+1564**), `ZI-data 121764` (**+864**) |
| `ARKRTOS_USE_MTX_RECURSIVE` | **no recursive create entry**: `arkrtos_mtx_create_recursive()` and SVC 0x15 sub-command 17 are not compiled; all locks in the table are plain locks (re-entry by the holder returns `-1`). Default off |
| `ARKRTOS_USE_WAITMULTI` | **no multi-object probe**: `arkrtos_wm_probe_internal()`, SVC 0x22, the dispatch case and the app-side `arkrtos_wait_multi()` are not compiled; waiting on several objects means polling with `timeout=0`. Default off |
| `ARKRTOS_USE_WAIT_UNBOUNDED` | `ARKRTOS_WQ_SLOTS` falls back to `ARKRTOS_MAX_SYNC_WAITERS` (4): **one derived macro only**, no logic changes, only the waiter-array lengths and static RAM. Default off |
| `ARKRTOS_USE_SMP` | **no SMP skeleton**: `arkrtos_smp.c` is an empty object, the `arkrtos_smp_init()` call in `arkrtos_kernel_module_init()` is not compiled, and the two strong port stubs `arkrtos_port_cpu_start()` / `arkrtos_port_send_ipi()` are not compiled. **On does not mean multi-core support** - the scheduler is still single-core. Default off; default profile `Code=220290`, byte-identical to before; on-profile size not measured (no multi-core board) |

### 3. Services and components

| Switch | What disappears when off |
|---|---|
| `ARKRTOS_USE_LOG` | kernel log and console both vanish. User code writing to the console handle takes **the ordinary device path** (`arkrtos_console_is_handle()` returns 0), not a black hole |
| `ARKRTOS_USE_LOG_RING` | no dmesg ring: the `dmesg` command disappears and history cannot be reviewed (live output remains if `ARKRTOS_USE_LOG=1`) |
| `ARKRTOS_USE_BLK` | block layer with an empty table; every read/write returns -1. **Dependency: `ARKRTOS_USE_FS` must be 0 too** |
| `ARKRTOS_USE_FS` | the filesystem facade reports "nothing mounted", with error codes matching reality |
| `ARKRTOS_USE_VFS` | no path namespace: `/dev` and `/mnt` are gone, shell `mount`/`ls`/`cat` and app path access all `NOSYS`. **Dependency: `ARKRTOS_USE_BLK` must be 1** |
| `ARKRTOS_USE_VFS_LFS` | no built-in persistent volume under `/mnt`: the kernel no longer bridges a block window into a littlefs volume; callers can still mount their own `fsdrv`. **Dependency: `ARKRTOS_USE_VFS`** |
| `ARKRTOS_USE_PROCFS` | no `/proc`: `version` / `uptime` / `meminfo` can no longer be read by path. **Dependency: `ARKRTOS_USE_VFS`** |
| `ARKRTOS_USE_POSIX` | apps lose `<pthread.h>` and must use the native oslib |
| `ARKRTOS_POSIX_WRAP_STDLIB` | the POSIX layer no longer routes `malloc/free` to its own heap (off by default anyway) |
| `ARKRTOS_USE_MINIAPP` | no mini-apps: the third kind of application ("read from the filesystem into RAM and execute") is gone, along with the shell `mini` command. **Dependency: `ARKRTOS_USE_FS`** |
| `ARKRTOS_MINI_MAX` | concurrent mini-app limit (compile-time, 1..4, default 2): out of range is a hard `#error`, not a silent clamp |
| `ARKRTOS_MINI_YIELD_CHUNKS` | `0` = hold the scheduler lock for the whole load, size and behaviour reverting to before this switch; default `1` = yield the scheduler once per chunk so the control loop is not frozen for the whole load |
| `ARKRTOS_USE_MDK_TRACE` | trace capture vanishes; 14 entries become empty implementations |
| `ARKRTOS_USE_SOFTBUS` | the cross-device soft bus is not in the binary at all: no events / remote calls / data plane, and the `bus` command disappears. Default off; when on the project must also supply the MCU-profile `-DARK_BUS_*`, otherwise `#error` |
| `ARKRTOS_USE_LWIP` | the lwIP port layer is not compiled: no socket/select base, and the 1 KB-stack service task is not registered. **Off by default** (the kernel region needs another 128 KB) |

### 4. Reliability and operations

| Switch | What disappears when off |
|---|---|
| `ARKRTOS_USE_IMAGE_SIGN` | no signature check at install: any image that reaches a slot is accepted. **Turning it on requires `ARKRTOS_IMAGE_SIGN_KEY` (32 bytes) or the build fails**. Default off (symmetric HMAC, not a full trust chain) |
| `ARKRTOS_USE_CRASH_LOG` | no cross-reset crash ledger: nothing recorded, images not disabled by fault count, region address 0 |
| `ARKRTOS_HW_SAFE` | the hardware safe-state ("last words") machinery is not compiled: device open/close and task reaping behave exactly as before it existed. Off means SVC 0x14 sub 4/5/6 do not exist and SVC 0x10 sub 6 returns -1 explicitly. Default off |
| `ARKRTOS_MINI_EXIT_IS_HANDOVER` | `0` = a mini-app main task exiting normally still runs last-words/callbacks and the hardware drops to safe state (one hiccup during seamless upgrade); default `1` = normal exit only unwinds the ledger and hands devices to the new version taking over. Meaningful only with `ARKRTOS_USE_MINIAPP=1` |
| `ARKRTOS_USE_KERNEL_GUARD` | no heartbeat contract: the record is a no-op and an **explicit heartbeat returns -1** (callers must not believe "somebody is watching") |
| `ARKRTOS_USE_AUDIT` | no structured self-check: the report is empty and the mask 0, which is "no findings", not a forged clean bill of health |
| `ARKRTOS_USE_UTEST` | the on-board unit test framework and the `utest` command are not compiled; size and behaviour unchanged |
| `ARKRTOS_USE_RTSTAT` | no real-time measurement (DWT cycle counting): tick timestamps, critical-section hooks, the `rt` command and the helper task are all absent, size and behaviour unchanged. On costs about +2.7 KB Code / +1.2 KB ZI (including a 1024 B helper stack) |
| `ARKRTOS_USE_SECCHECK` | no security baseline self-check (`sec` command): every entity in `arkrtos_sec.c`, the command and its budget are absent, size and behaviour unchanged. On costs **+2056 B Code** on F427 (RO/RW/ZI unchanged) |
| `ARKRTOS_USE_TASK_SWAP` | true/false seamless upgrade (A/B double-buffer hot switch) does not exist: the four kernel swap primitives, both consumers (mini-app and app), the two SVC landing hooks, and `mini swap` / `app swap` are absent. Default `Code` is 219882 (i.e. **+48 B** against before the feature, from `arkrtos_mini_load_image` no longer being inlined - **not byte-identical**). F427 measured (same project, only this macro changed): on profile `Code=222614`, `RO-data=20114`, `ZI-data=121116`, i.e. **+2700 / +916 / +264** with `0 Error(s), 4 Warning(s)`; `mini swap` / `app swap` both verified on hardware (old block returned to the pool, old slot kept `LOADED`, switch-back works), but **the data section is reset by the startup stub**. Since 2026-11-20 the non-ARM frame rewrites are implemented: frame handling moved into the port layer (`arkrtos_port_swap_frame_bytes / rewrite / activate`), RV32 rewrites `a0..a7 / sp / mepc / mstatus` and LA64 rewrites `a0..a7 / sp / ERA / PRMD`; QEMU kernel self-test readings are 5/5 (RV32) and 3/3 (LA64) `swap: PASS`. RV64GC and LA32 with this switch ON are still a compile-time `#error`. See [跨架构机制矩阵](跨架构机制矩阵.en.md) |
| `ARKRTOS_USE_CM_BACKTRACE` | the exception backtrace component is not compiled |
| `ARKRTOS_USE_SHELL_AUTH` | **the console needs no password**: `arkrtos_shell_auth.c` is an empty object, no gate hook is installed in the shell task, `login`/`logout` are not registered, the prompt works right after boot, size and behaviour unchanged. Default 0; **requires `ARKRTOS_USE_SHELL` (turning shell off and then enabling this is a hard `#error`)**. Turning it on also requires a 16-byte salt and a 32-byte `sha256(salt || password)` digest (`ARKRTOS_SHELL_AUTH_SALT` / `ARKRTOS_SHELL_AUTH_DIGEST`, generated by `tools/shell_auth_cred.py`, delivered through the gitignored `*_shell_auth_local.h` channel); missing either is a hard `#error` - no false green of "enabled but nobody can log in" or "there is a universal default password". QEMU LA64 measured **+3576 B text / +24 B data** (366744/416/767508 -> 370320/440/767508). Honest boundaries: the password crosses the serial port in clear text, an image leak allows offline brute force, and it is **not a device identity** (that is SEC-G13) |
| `ARKRTOS_SHELL_AUTH_TRIES` | tolerated consecutive wrong passwords (1..100, default 5): at the limit the console **hard-locks until the next reset** (correct passwords are refused too), so a serial brute force needs a board reboot every `TRIES` attempts. No exponential backoff: serial is a slow link and backoff only makes each attempt cheaper per unit time |
| `ARKRTOS_USE_GDBSTUB` | The GDB remote serial protocol (RSP) agent does not exist: `arkrtos_gdbstub.c` compiles to an empty object (no symbols) and the image and behaviour are bit-for-bit unchanged. Default 0. Even when on there is no `c`/`s`/`vCont` (the agent is polled by its caller and has no execution stream to take over) and no `Z0`/`z0` breakpoints; unsupported packets get the empty packet, never `OK`; and there is **no authentication**, so it belongs on a debug port only. 193 host assertions, see [单元测试框架](单元测试框架.en.md) and section 5 of [已知限制](已知限制.en.md) |

### 5. On-board direct-build knobs (example Makefile switches)

This layer is not kernel capability but **which "let the board compile and run by
itself" parts are compiled into this build**. Knobs sit at the top of
`example/stm32h743/kernel/ARKRTOS_TEST/GCC/Makefile` (`USE_ARKVIM ?= 1` and so on);
when off, the corresponding source file **does not take part in the build at all**.

Value chain since 2026-11-14: `make USE_XXX=0` -> written into this build's per-build
defconfig -> per-build `arkrtos_autoconf.h` -> both the source list and the kernel-side
gating follow `ARKRTOS_USE_*`. `DEFS` no longer holds feature macros, so a knob cannot
drift out of sync with the kernel just because the command line changed.

| Switch | What disappears when off |
|---|---|
| `USE_ARKVIM` | the on-board `vim` command (the editor is not in the binary) |
| `USE_ARKC` | the on-board `cc` command (the on-board compiler). Requires `ARKRTOS_USE_VFS=1`; an impossible combination is stopped by `#error` at compile time, not at link time |
| `USE_APPRUN` | the `app run` direct-run entry with a fixed RAM window; `arkrtos_apprun.c` becomes an empty object |
| `USE_ARKMAKE` | the on-board `make` command. Requires `USE_ARKC=1` and `USE_APPPACK=1` (its packaging callback is the `cc --pack` body); otherwise the `#error` in `arkrtos_features.h` stops it at compile time |
| `USE_APPPACK` | `cc --pack` reports `option '--pack' is not supported by this build`: the four-pass differential packer is not in the binary, so **no `.svcm` can be produced** |
| `USE_MINI_VFS` | `mini run` reverts to reading images from the `arkrtos_fs` volume (byte-identical to before the switch); **mount-point paths like `/mnt/...` require it on** |
| `USE_QSPI` | QUADSPI clock and pins are untouched, `drvqspi.c` is not compiled, the `nor` command disappears and `nor0` is not registered; since 2026-11-07 it also decides whether `/mnt/nor` automounts at boot (`ARKRTOS_AUTOMOUNT_NOR=$(USE_QSPI)`): project files live on NOR and `cd /mnt/nor && make` is the demo mainline, without a manual `fs mount` + `mount` |
| `USE_SDRAM` | external SDRAM not enabled; compiler buffers and ramfs stay on-chip (off by default). **Usable on hardware since 2026-11-07**: what was missing was `FMC_BCR1.FMCEN`; after that `sdram test` PASSes all 32 MB, and with `USE_SDRAM=1` on-chip RAM drops from 98.37% to 62.14% while the compiler pool goes 80 KB -> 4 MB. When enabled, boot verifies the window before mounting VFS (`ARKRTOS_SDRAM_VERIFY_AT_BOOT`, default 1) |
| `ARKRTOS_PACK_IN_EXTRAM` | the four 16 KB payloads plus 16 KB object/image buffers of `cc --pack` fall back to borrowing the on-chip RAM pool (the board macro follows `USE_SDRAM`). Default 0 is **byte-identical** to before the switch; when on, the whole 80 KB goes to `.extram` (SDRAMFS partition, NOLOAD) and the window grows from 8 KB to 16 KB - four sources are about 7.7 KB of payload and do not fit in 8 KB |
| `ARKRTOS_AUTOMOUNT_NOR` | no NOR volume mounted at boot (no print, no littlefs/VFS mount path touched). Default 0; enabling it requires `USE_QSPI=1` + `USE_FS=1` + `USE_VFS=1` + `USE_VFS_LFS=1`, otherwise `#error` |
| `MINI_PRIORITY` | empty = the kernel default `APP_TASK_PRIORITY` (10), which is **above the console (14)**: a `for(;;)` mini-app starves the shell forever and the prompt never returns after `mini run` (measured this round). The demo/regression projects default to **20** (the same rule as `ARKRTOS_APPRUN_PRIORITY`); `make MINI_PRIORITY=` reproduces the kernel default |

> **Since 2026-11-14 this is automatic in GCC projects**: each `USE_*` knob enters the
> per-build defconfig -> per-build autoconf.h -> `-MMD` dependency mismatch -> rebuild.
> A manual `make clean` is only needed for "changed the partition header" or "changed the
> source list (sources.mk)".
>
> Historical fact: before that, `make` **did not track `-D` or header changes**, so you
> had to `make clean` after switching a knob or editing the partition header, or you would
> link a "looks right, knob never took effect" image. (Since 2026-11-07 there is a
> mechanical fallback: every switch value that changes the image goes into the
> `build/.ldcfg` fingerprint and participates in the `.o` and `kernel.ld` dependencies;
> partition-header changes still rely on `.d` dependencies. The fingerprint covers knobs,
> not external hand-edited `-D`; the two ramfs numbers (`ARK_RAMFS_FILE_CAP` /
> `ARK_RAMFS_MAX_FILES`) are in it because changing them is changing `-D`. It was hit once
> this round: after raising the slot count to 11 only edge files changed size and the new
> limit was not compiled in.)

### 6. Kernel-side switches for the on-board direct-build components (`ARKRTOS_USE_*`)

The knobs in section 5 are at the **example Makefile** level, deciding whether a component
is in this image. The ten below are the **kernel-side gating** of the same components (in
`kernelsrc/include/arkrtos_features.h`, each with a Kconfig symbol, all defaulting to 0).
They are not alternatives: the Makefile decides "does the source file enter this build",
the kernel switch decides "do the kernel half and the SVC entry enter the binary".

| Switch | What disappears when off |
|---|---|
| `ARKRTOS_USE_APPRUN` | no fixed-RAM-window direct-run entry: `arkrtos_apprun.c` is an empty object, `app run` disappears. **Requires `ARKRTOS_USE_VFS=1`** |
| `ARKRTOS_USE_FLASHAPP` | the "read an image from the filesystem and execute it" path disappears, and the bridge reusing the app-run window for data/stack is not registered. **Requires `ARKRTOS_USE_APPRUN=1` and `ARKRTOS_USE_VFS=1`** |
| `ARKRTOS_USE_APPPACK` | the four-pass differential packer (the `cc --pack` body) is not in the binary: `option '--pack' is not supported by this build`, no `.svcm` |
| `ARKRTOS_USE_ARKC` | the on-board compiler is not in the binary, `cc` disappears. **Requires `ARKRTOS_USE_VFS=1`** (sources and products both go through the VFS namespace) |
| `ARKRTOS_USE_ARKMAKE` | the on-board `make` disappears. **Requires `ARKRTOS_USE_ARKC=1` and `ARKRTOS_USE_APPPACK=1`** (its packaging callback is the same packer) |
| `ARKRTOS_USE_ARKVIM` | the on-board `vim` editor is not in the binary. **Requires `ARKRTOS_USE_VFS=1`** |
| `ARKRTOS_USE_QSPI` | QUADSPI clock and pins untouched, no `nor` command and no `nor0` block device; when `ARKRTOS_AUTOMOUNT_NOR=1` this must be 1 or `#error` |
| `ARKRTOS_USE_SDRAM` | external SDRAM not enabled: compiler buffers and ramfs stay on-chip. When enabled, boot verifies the window before mounting VFS (`ARKRTOS_SDRAM_VERIFY_AT_BOOT`, default 1) |
| `ARKRTOS_USE_ELF` | no ELF64 executable loader: `kernelsrc/src/arkrtos_elf.c` is an empty object, the `exec` command and the "type an executable path" fallback are not registered (typing a path yields "not found", never an entry that pretends to run), size and behaviour unchanged. **Requires `ARKRTOS_USE_VFS=1` and `ARKRTOS_USE_PRIV=1`**; when on, the board must provide `ARKRTOS_ELF_WINDOW_BASE` / `ARKRTOS_ELF_WINDOW_SIZE` (the PLV3 user window) or `#error`. When on, the example no longer registers the PLV3 privilege-isolation probe task (both want the same 2 MB user page; `ARK_EXAMPLE_PLV3_PROBE` decides, and the boot log says why) |
| `ARKRTOS_USE_FDT` | no in-kernel FDT parser: `kernelsrc/src/arkrtos_fdt.c` becomes an empty object (the off-tier .o has an empty symbol table), no `arkrtos_fdt_*` symbol exists, the `[fdt]` boot line is not printed and the `fdt` shell command is not registered, size and behaviour unchanged. This tier is enabled by the **board layer** (MMU tier: `config/<board>_defconfig` asks for `=y`, block seven of `genboard.py` writes the override); the shared `arkrtos_autoconf.h` keeps it 0 and the MCU + MDK tier stays off. See [Device Tree](设备树.en.md) section 5.1 |
| `ARKRTOS_USE_FDT_CONSOLE` | turns off the `/chosen/stdout-path` consumption check: `arkrtos_fdt_console.c` becomes an empty object, the `[fdt] console ...` boot line is not printed and the `fdt chosen` subcommand is not registered. Depends on `ARKRTOS_USE_FDT` (meaningless while that is 0); default 0, enabled only by the LA64 board. It only judges and never changes the console: on a mismatch the board default is kept and a reason code is reported. See [Device Tree](设备树.en.md) section 5.2 |
| `ARKRTOS_USE_FDT_OVERLAY` | turns off dtb overlays: `arkrtos_fdt_overlay.c` becomes an empty object (empty symbol table), the `fdt overlay` subcommand is not registered, and the board's `arkrtos_board_fdt_overlay_demo()` plus its fragment C array are not compiled in either - zero size and behaviour change. Depends on `ARKRTOS_USE_FDT`; default 0, enabled only by the LA64 board. What is implemented is a **minimal subset**: `target-path` absolute paths, same-name property overwrite, new child node append. `target = <&label>` / `__fixups__` / `__symbols__` / deletion semantics / a same-named child already under the target are all rejected by code with the caller's tree untouched. See [Device Tree](设备树.en.md) section 5.3 |
| `ARKRTOS_USE_MODLOAD` | no VxWorks-style downloadable modules: `arkrtos_modld.c` / `arkrtos_exports.c` are empty objects, the `ld` / `lkup` / `modules` / `unld` commands are not registered, size and behaviour unchanged. **Requires `ARKRTOS_USE_VFS=1` and `ARKRTOS_USE_PRIV=1`**; the board only supplies `ARKRTOS_MOD_AREA_SIZE` (module pool size) and the linker places the pool. **This is a second application model alongside `ARKRTOS_USE_ELF`, not a replacement**: ELF is `ET_EXEC` + PLV3 isolation, MODLOAD is `ET_REL` + PLV0; each can be on alone or both on (all four 2x2 combinations compile). Modules run in kernel mode with no memory isolation - the VxWorks 5.x trade-off |

## The two isolation backends (`ARKRTOS_USE_MPU` / `ARKRTOS_USE_PAGING`)

The kernel has exactly one isolation contract (`kernelsrc/include/arkrtos_mpu.h`):
`arkrtos_mpu_module_init` / `_build_task` / `_set_app` / `_set_idle` / `_reset`. `mpu` in
those names is historical; eight call sites use it, and the semantics are "attach this
task's isolation context".

Two implementations, **chosen by switch**, only one compiled at a time:

| Backend | Switch | File | Isolation by | Applies to |
|---|---|---|---|---|
| Window | `ARKRTOS_USE_MPU=1` | `kernelsrc/src/arkrtos_mpu.c` | ARM MPU / RISC-V PMP physical window registers | Cortex-M3/M4/M7, RV32IMAC (PMP) |
| Page table | `ARKRTOS_USE_PAGING=1` | `kernelsrc/src/arkrtos_paging.c` | TLB mapping plus privilege level (PLV0 / PLV3) | LoongArch LA32/LA64; a future RV64 port |

Three guards in `arkrtos_config.h`, all `#error`, no silent downgrade:

1. `ARKRTOS_USE_PAGING=1` but this core has `ARKRTOS_ARCH_HAS_PAGING_HW != 1`;
2. `ARKRTOS_USE_PAGING=1` together with `ARKRTOS_USE_MPU=1`;
3. `ARKRTOS_USE_PAGING=1` but `ARKRTOS_USE_PRIV != 1`.

`ARKRTOS_ARCH_HAS_PAGING_HW` is a **hardware fact** (does this core have a TLB/page
table); `ARKRTOS_USE_PAGING` is **whether this build uses it**. Do not mix them: RV64GC
has the hardware bit at 1, but there is no RV64 port yet so `USE_PAGING` is still 0;
`arkrtos_sec.c`'s `iso=` reads only the latter, otherwise it would report an isolation
that was never switched on (a false green).

Where the value comes from: Keil / GCC projects use Kconfig (`config ARKRTOS_USE_PAGING`,
default `n`, landing in `arkrtos_autoconf.h`); the QEMU examples do not use
`autoconf.h`, so `board/qemu_loongarch64/arkrtos_board_config.h` sets it to 1 directly.

What this backend really does and does **not** do is in
[内存保护与App越权验证.en.md](内存保护与App越权验证.en.md) §7.

## Two implementation rules

**Rule one: a module called from a kernel hot path uses whole-file gating plus
`#else` stubs.** `tick`, the SVC dispatcher and device writes should not be littered with
`#if`, or the code reads like a patch. Stubs always answer "no": failure returns -1,
queries return 0, NULL or `n/a`. Never a value that looks like success.

**Rule two: a switch that must be 1 is blocked by `#error`, not left to the linker.**
`ARKRTOS_USE_SCHED_LOCK` is the example: kernel call sites have no off branch, so setting
it to 0 blows up 14 symbols at link time. `ARKRTOS_USE_FS=1 && ARKRTOS_USE_BLK=0` likewise.
Dependencies live at the end of `arkrtos_features.h` so the compiler says it up front.

## How to verify "it really switches off": build the minimal profile

Do not edit the defaults in `arkrtos_features.h` to "try trimming" - that pollutes the
sources. **Swap the defconfig** instead; not one line of source changes:

```bash
# 1) swap defconfig and regenerate autoconf.h (no source change)
py -3 tools/kconfig/genconfig.py --kconfig Kconfig \
    --defconfig config/minimal_defconfig \
    --out kernelsrc/include/arkrtos_autoconf.h

# 2) full rebuild (-r; -o into C:\tmp; exit code 1 only means warnings)
UV4 -r <project>.uvprojx -o C:\tmp\trim.log -j0

# 3) restore autoconf.h from the default defconfig
py -3 tools/kconfig/genconfig.py --kconfig Kconfig \
    --defconfig config/arkrtos_defconfig \
    --out kernelsrc/include/arkrtos_autoconf.h
```

The criterion is **0 Error(s)** plus a generated `.axf`; read `Program Size:` at the end of
the log.

### Three things Kconfig alone could not trim (all fixed 2026-11-14)

> This section keeps the failure shapes as evidence for "why project macros had to be
> zeroed out". Current status is in parentheses after each heading.

1. **Project macros beat Kconfig.** Every line of `arkrtos_autoconf.h` is `#ifndef`, and a
   command-line `-D` applies before any header, so the `ARKRTOS_USE_LWIP=1` and friends
   hardcoded in uVision's `Options -> C/C++ -> Define` could not be switched off from
   Kconfig (trimming died the second time at
   `#error "ARKRTOS_USE_LWIP=1 requires ARKRTOS_USE_MQ=1"`). **Fixed (2026-11-14)**: the
   feature macros in all three projects are zeroed out; the 5 forced switches moved into
   `config/arkrtos_defconfig` and `<Define>` keeps only
   `USE_HAL_DRIVER,STM32F427xx,ARKRTOS_BOARD_CONFIG="..."`.
2. **Translation units that included `features.h` directly did not see Kconfig values.**
   (**Fixed**) The file did not include `autoconf.h` itself, so whoever defined first won:
   a few `.c` files including it directly got the `features.h` defaults (mostly 1) and
   compiled the implementation even with Kconfig saying `n`, surfacing later as
   `L6218E: Undefined symbol arkrtos_fs_mkdir`. `features.h` now includes `autoconf.h` at
   the top (default-profile sizes unchanged item by item).
3. **The soft-bus port glue had no switch guard.** (**Fixed**: guard added in the
   ark_softbus source repo on 2026-11-14, then `sync_ark_softbus.py --apply`;
   with `ARKRTOS_USE_SOFTBUS=0` the file compiles to an empty object, so the project file
   table can **keep** it and still link with 0 errors.) Before that the minimal profile had
   to delete that entry from the project table (Keil's per-file `IncludeInBuild=0` does not
   work for `.o`; the `<File>` block had to go). The fix belongs in the ark_softbus source
   repo - **never edit the vendored copy**.

### A second real defect caught the same round: the utest header inside the MEMPOOL block

The minimal profile (MEMPOOL off, UTEST on) failed with
`error: #20: identifier "ark_utest_summary_t" is undefined`: `arkrtos_shell.c` had
`#include "arkrtos_utest.h"` inside `#if ARKRTOS_USE_MEMPOOL` while the use site was inside
`#if ARKRTOS_USE_UTEST`, so any build where the two differ failed to compile. Now it has
its own gate `#if (ARKRTOS_USE_UTEST == 1)`; default-profile sizes unchanged
(220094 / 19198 / 896 / 120852).

Also, the shell switch is a Kconfig symbol now (`ARKRTOS_USE_SHELL`). Measured: turning it
off saves **33184 B Flash / 14620 B RAM** - the single largest block, because it carries
the whole command line, completion, history and command table.

### What is left inside 37.8 KB (aggregated from `.map`)

| Part | Size | Note |
|---|---|---|
| kernel core | ~24.9 KB | task 6.5 / loader 6.3 / sync 3.2 / ptable 2.4 / installer 1.8 / layout 1.2 / port 0.7 / dev 0.6 / event 0.6 / mpu 0.4 ... |
| board HAL + drivers | ~7.4 KB | spi 1.8 / rcc 1.3+0.6 / gpio 0.6 / flash 0.6 / nor 1.0 / uart 0.4 / led 0.4 / rtc 0.3 |
| demo application `main.o` | 1.1 KB | not kernel |
| C library printf family | ~1.3 KB | what is left after kernel logging is off |

So going lower is no longer "turning switches off" but cutting capability itself (the
loader/installer are the implementation of the "install applications + crash accounting"
selling point) or replacing the board HAL module set. The floor of the "minimal profile" is
**~38 KB Flash / ~28 KB RAM (10 KB of which is the demo application's own buffers; the
kernel itself is ~18.9 KB RAM)**.

### Default profile unchanged (self-proof of this fix)

After `#include "arkrtos_autoconf.h"` was added at the top of `features.h`, the 51 symbol
values of the default `arkrtos_defconfig` were compared one by one with the fallback
defaults in `features.h`: **all 51 identical**. A full default-profile rebuild in a clean
worktree gave `Code=220094 RO-data=19198 RW-data=896 ZI-data=120852`, `0 Error(s)
5 warning(s)`, **identical item by item**. The board-side AC5 vector's new
`ARKRTOS_USE_MDK_TRACE == 1` condition also holds in the default profile, so it is
unchanged.

## Checklist for adding a switch

1. add `#ifndef / #define / #endif` in the right group of `arkrtos_features.h`;
2. add whole-file gating in the implementation, and state in the `#else` what callers see
   when it is off;
3. if the kernel calls it, make sure a stub keeps the symbols linkable, or declare
   "must be 1" with `#error`;
4. build once with everything off: 0 errors;
5. build once with everything on: Code matches the baseline.

## Division of labour with Kconfig (settled 2026-11-14)

* `arkrtos_features.h` remains the home of `#if ARKRTOS_USE_XXX` in the code;
* **Kconfig alone decides** the values of those macros and guarantees a legal combination
  (e.g. `ARKRTOS_USE_FS` depends on `ARKRTOS_USE_BLK`);
* the board header only answers "what does this board have and how much", never "what does
  this build want".

The value chain of the three projects:

```
F427/F401 Keil --> kernelsrc/include/arkrtos_autoconf.h   (= config/arkrtos_defconfig)
                        ^
                        | (shadowing, GCC only)
H743/F427 GCC --> build/kconfig/arkrtos_autoconf.h        (= config/<board>_defconfig + knobs)
                        |  -I placed first => the shared header is shadowed
```

Key points:

1. the shared header is a **committed product**, and the `kconfig-sync` style checks in
   `tools/ci_gate.py` require it to equal the output of `config/arkrtos_defconfig`;
2. GCC projects shadow the shared header with a per-build header, so the two F427 projects
   can hold different configurations without affecting each other (Keil has RTSTAT/SECCHECK
   on, GCC has them off - because Flash was at 99.1%);
3. `#ifndef` is still there and a command-line `-D` still technically takes precedence -
   but there are no feature macros in project files any more; the only remaining `-D` are
   board capability and upstream component budgets (see the top of this page).

Menus, tools, the `--kconfig` argument, the shadowing mechanism and the three defconfigs
are in the Kconfig page §8.

Incidentally: the limits that used to be hardcoded in various places (task table / sync
table / queues / timers / sockets / fds) are Kconfig symbols now, with defaults identical
to the past - behaviour without running Kconfig is unchanged.
