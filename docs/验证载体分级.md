# 验证载体分级：QEMU 算上板，但不是真机

这个仓库里"测过了"有三种完全不同的分量，而在散文里它们长得一模一样。这一页
把分量变成一列可以机械校验的数据，好让"QEMU 算上板"这句话不再有第二种读法。

## 1. 四档

| 级别 | 名字 | 证明了什么 | 不能证明什么 |
|---|---|---|---|
| **L1** | 编译面 | 这个配置编得过、链接得过、符号该有有该无无 | 跑起来会怎样（一行都没执行） |
| **L2** | QEMU 运行 | 在**指定的** QEMU 机型上真跑出了这串读数 | 硅片上的时序、TLB/缓存语义、外设模型、中断延迟 |
| **L3** | 真机 | 板子上的串口日志 | 别的板子、别的批次、别的工况 |
| **L0** | 无载体 | 什么都没有（也可能是**编译期拒绝**——那是设计，不是欠账） | — |

两条容易混的边界，先说死：

- **编译期拒绝 ≠ 未验证。** `LA32` / `RV64GC` 的无缝衔接是 `#error` 主动拒绝，
  属于 L0 但**不是欠账**：它保证的是"不给错答案"，不是"还没做"。
- **L2 不等于 L3。** 换机型（QEMU `virt` 的 RV32 / LA64 / `mps2-an386`）是换
  载体，不是换级别。本仓库没有任何一条 L2 读数被写成"已上板"。

## 2. 台账是唯一来源

每条主张的级别、载体、出处都在 `tools/evidence_levels.tsv` 里，一行一条。本页
只做解释，不重复数据——两处写同一件事，迟早会不一致。

台账当前 20 行：**L3 = 4 行（全部是 STM32F427）**、L2 = 11 行、L1 = 3 行、
L0 = 2 行。也就是说：**这个仓库里能叫"上板"的读数，只来自一块板。**

门禁 `tools/evidence_gate.py`（CI 项名 `evidence-levels`）逐条校验：

1. 五列固定，`level` 只能是 L0/L1/L2/L3；
2. **L2 的载体必须是存在的 `board/qemu_*` 目录**——写错机型名就红；
3. **L3 的载体必须是存在的真实板级目录，且不能是 `qemu_*`**——QEMU 永远升不成 L3；
4. L2/L3 的证据里必须有一个**本仓库 git 历史里真实存在**的提交号
   （`git cat-file -e` 查不到就红），防止"我们测过"这种无出处的主张；
5. L1 的证据必须写 `gate:<脚本>` 或提交号（编译面的出处是门禁，不是日志）；
6. L0 的载体必须是 `none`；
7. **L3 行数冻结**成 `L3_FROZEN = 4`。增加一条真机读数必须同时改这个常量——
   硅片读数只能靠人把板子上的串口日志抄回来，不能靠改代码"长"出来，所以
   那必须是一个刻意动作。

## 3. QEMU 为什么升不成 L3：三条本仓库已经踩到的实证

不是"模拟器天然不可信"这种空话，是三条具体的、在这个仓库里已经吃过亏的差异：

**(1) TLB / ASID 语义。** 每空间 ASID（U-7）这条线上，`invtlb` 的定向失效在
QEMU 上实测：`op 0/1/2/6` = 整表清空并立刻 `KERNEL refill fatal`、`op 4/5` =
空操作、`op 7` = 非法指令、`op 3` = 按 VA 且**不看 ASID**。于是
`space_release` 只能保留"切 ASID → 按 VA 撤 → 切回 → 补铺"这条路。硅片上
`invtlb` 的 op 语义由手册规定、与 QEMU 不必一致；另有一条已知的 QEMU 缺陷
（`tlbwr` 不刷新大页**奇页**，README 里那次"切换静默失效"就是它）。这些读数
是 L2：它们证明代码在**这个模拟器**上自洽，不证明在硅片上自洽。

**(2) 时序。** 实时性仪表 `ARKRTOS_USE_RTSTAT` 从 2026-11-20 起三档都能报周期数，
但**读数的来源不同**：ARM 走 DWT `CYCCNT`（真机 `switch` 744 cyc = 7.75 µs、
`tick.isr` 6.3 µs 平均 / 71.6 µs 最大）；RV32 读 `mcycle`；LA64 读稳定计数器，
分母只能取板级常量。QEMU 实测：RV32
`cycles per tick: 1554266 (3108533020 Hz [measured], 499 us)`、
`tick.isr N=805 AVG 38us MAX 7714us`；LA64
`cycles per tick: 50000 (cycle clock 100000000 Hz [board constant], tick 500 us)`。
两处限定必须一起读：RV32 的 `[measured]` 频率是在 QEMU 内部量出来的，与宿主
调度有关，**不是硅片频率**；LA64 的分母是常量，给出的是自洽的相对值。所以
跨档的 µs 数字既不可横向比较，也不是最坏延迟。QEMU 仍然没有 cache / 流水线 /
总线仲裁模型，非 ARM 这几档证的是**结构与计数口径**（每拍都切、关中断窗口
有界、能报周期数），证不了**最坏延迟**。

**(3) 外设与真实事件。** 遗言（`ARKRTOS_HW_SAFE`）在 QEMU 上曾只能打
`devs=0 owners=2 neutralized=0` 这种台账行——"按契约把设备带回安全态"那条路径
根本没人走。2026-11-20 起板级桩登记了 3 个设备（含 will 与 led 中和回调），
QEMU 读数变成 RV32
`hwsafe: enabled, devs=3 owners=3 neutralized=2 (will=1 cb=1 none=0 fail=0 handover=0) last_owner=9`、
LA64 `neutralized=3 (will=1 cb=1 none=1 ...)`，任务死亡后
`[hwsafe] after deaths: ... safe_hits=1 led0=0 led1=0 led2=1`。这条路径在 L2 上
被走过了，但它证的是**回调被调用、参数对得上**，不是电气状态恢复：QEMU 的
"设备"是板级桩，没有引脚、没有外设寄存器副作用。真机 F427 的
`devs=3 owners=6 neutralized=6 last_owner=12` 仍是唯一一条全路径读数。同型的
还有：崩因上限跨复位、真实 PHY / MDIO / RMII（lwIP 只跑过回环）。

## 4. 把某一行从 L2 升到 L3，最小要做什么

| 档位 | 需要的硬件 | 要抓的串口行 | 判定串 | 现状 |
|---|---|---|---|---|
| Cortex-M7 / H743 | 现成 `board/stm32h743` + GCC 工程，**只需把 `ARKRTOS_HW_SAFE` / `ARKRTOS_USE_RTSTAT` 打开烧一次** | `[HWS] devs=... owners=... neutralized=...`、`rt` 的 `switch ... cyc` | `neutralized` 与 `owners` 同时非 0；`rt` 出周期数而不是 `-1` | L1（开关默认关，无读数） |
| Cortex-M3 | 板级工程（本仓库 M3 只有 Keil `AREA`/`PROC` 上下文切换，没有工程） | `swap: PASS` | 与非 ARM 同一条判据 | L1 |
| RV32IMAC | 一块 RV32IMAC 板 | 内核自检 `swap: v1=7 -> 7 v2=100` | `swap: PASS` | L2（QEMU `virt`，5/5） |
| LA64 | LA64 硬件（2K1000 / 3A5000 级），成本高 | 同上 | 同上 | L2（QEMU `virt`，3/3） |
| LA32 / RV64GC | 载体本机不可得（见欠账盘点"LoongArch32 执行载体"一行） | — | — | L0（编译期拒绝） |

**这一页没有新增任何读数。** 上表最后两列如实写的是"现状"，不是"计划"。

## 5. 边界

1. 本页不声明"QEMU 上的结论在硅片上也成立"；它声明的是**每条结论的载体是
   谁**，并且这个归属可以被机器检查。
2. 台账不判断证据内容与主张是否相符（那要靠人读日志）；它管的是**台账本身
   不许自欺**。
3. 新功能默认关档零变化这条纪律不因为本页改变：新功能进台账时级别怎么写，
   取决于它到底在哪个载体上留下了读数。
