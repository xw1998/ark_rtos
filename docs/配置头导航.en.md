# Configuration header map

**[简体中文](配置头导航.md) | English**

> Condensed English edition. The Chinese page (配置头导航.md) is normative: every number below is
> copied from it as of 2026-11-18, but if the two disagree, the Chinese page wins. This page adds no
> new claim and no new measurement.

## In one line

"Which header do I touch to change this?" is not answered from memory in this repo: addresses have one
source, switches have one landing point, generated files must not be hand-edited, and four gates turn
these rules red. This page is that map — **boundaries and landing points only**, not how the tools
work (tools are in [Kconfig配置系统.md](Kconfig配置系统.md), per-switch semantics in
[功能开关.md](功能开关.md)).

## 0. What I want to change → which file

| What I want to change | Touch this | Do not touch | Must do afterwards |
|---|---|---|---|
| Size of some object table, queue depth, timeout/capacity cap (`SEM_NUM`, `MQ_DEPTH`, `POSIX_FD_MAX`, ...) | `config/arkrtos_defconfig` (plus the `range` in `config/kconfig/Kconfig.capacity` if needed) | `kernelsrc/include/arkrtos_autoconf.h` (generated) | regenerate autoconf.h; `config-generated` gate |
| Turn a feature switch on/off | the Kconfig symbol (`config/kconfig/Kconfig.features` + defconfig); the `#if` landing point in code is still `arkrtos_features.h` | changing a default in `arkrtos_features.h` from 0 to 1 (that silently changes the build shape and menuconfig cannot see it) | compile once all-off, once all-on |
| What this chip **has** (FPU / MPU / privilege level / clock / watchdog) | `board/<chip>/arkrtos_board_config.h` | the capability fallback defaults in `arkrtos_config.h` | rebuild that board's project |
| Flash / RAM addresses, partition sizes, image-pool granularity, slot table, task table `ARKRTOS_TASK_MAX_NUM`, shell device name/priority/stack size | `config/arkrtos_partition.h` (F427) or `config/stm32f401|stm32h743/arkrtos_partition.h` | any `.sct`, any hard-coded address in a C file or script | `gen_scatter.py --check`, regenerate `.sct`, judge whether the config area must be reflashed / images reinstalled |
| An App or driver needs to know layout and slots | runtime via SVC `0x18` (the partition table in `arkrtos_share.h`) | `#include "arkrtos_partition.h"` on the App side | `no-app-partition-include` gate |
| Fields and semantics of the persistent device configuration record (install policy, fixed slot table, runtime knobs) | `kernelsrc/include/arkrtos_layout_def.h` (format) + `tools/arkrtos_cfg.py` (writer) | putting addresses into this header | compile-time size assertions; upgrade host tool and firmware in pairs |
| Handle flags, SVC call numbers, return codes, wake reasons | `kernelsrc/include/arkrtos_def.h` | hex magic numbers scattered around | change SDK side and kernel side together |
| Tick period, device/timer/fault-record counts, MPU peripheral windows, stack fill pattern | `kernelsrc/include/arkrtos_config.h` | — | rebuild that board |
| Task table declaration, boot load entry, task stack init | `kernelsrc/include/arkrtos_cfg.h` | — | rebuild that board |

> The three partition headers are **three instances of one role**: `config/arkrtos_partition.h` is
> the STM32F427 one, and `config/stm32f401/` and `config/stm32h743/` each have their own. Projects
> select one through the include path, scripts point at one with `gen_scatter.py --header <path>`.
> They are mutually independent; there is no "main header plus override header" relation.

## 1. Include order (the order itself is a contract)

```
board/<chip>/arkrtos_board_config.h      ← capability layer; pulled in by -DARKRTOS_BOARD_CONFIG="arkrtos_board_config.h"
        │  the first thing arkrtos_config.h includes
        ▼
kernelsrc/include/arkrtos_types.h
        └── arkrtos_autoconf.h           ← Kconfig output; symbol name = macro name, all inside #ifndef

arkrtos_config.h
        ├── config/<chip>/arkrtos_partition.h   ← the single source of addresses and capacities
        ├── arkrtos_arch.h                      ← architecture family / core / derived capabilities
        └── arkrtos_features.h                  ← optional layer (53 gates)

arkrtos_def.h        ──► arkrtos_types.h        ← handle flags / SVC numbers / return codes / wake reasons
arkrtos_cfg.h        ──► def.h + task.h + config.h
arkrtos_layout_def.h ──► types.h（**only** it, never a partition header）
```

Two places in that order are not accidental; changing them silently changes semantics:

1. **Board configuration comes before everything.** It must be able to override
   `ARKRTOS_ARCH_CORE` and the gate defaults, so it must precede `arkrtos_arch.h` /
   `arkrtos_features.h`.
2. **`autoconf.h` hangs off `arkrtos_types.h`.** `types.h` is the lowest header every translation
   unit of kernel and SDK reaches, so the generated values take effect both for the App side (POSIX /
   socket capacities) and the kernel side.

## 2. The seven headers, one boundary statement each

### 2.1 `config/<chip>/arkrtos_partition.h` — the single address source

- The only file in the whole project allowed to contain physical Flash / RAM addresses; the F427
  version has 95 `ARKRTOS_*` macros, and `.sct` files, C files and scripts must not hard-code
  addresses.
- Structure is "three sections + derivation": 1) chip physical parameters (a port changes only these
  lines); 2) partition size policy; 3) everything below is derived and **must not be hand-edited**.
  The derivation section holds `IMAGE_POOL_BASE`, `SLOT_RAM_BASE`, the `ARKRTOS_MPU_*` windows,
  `CRASH_LOG_BASE`, etc.
- Capacities live here too: `ARKRTOS_TASK_MAX_NUM` / `ARKRTOS_TASK_TABLE_RAM_MAX` were explicitly
  moved here from `arkrtos_config.h`, with the reason in the comments — a capacity change must not
  tell a different story than the layout.
- Remaining items that are here and are **not** Kconfig symbols: `INSTALLER_ENABLE`,
  `APP_AUTO_START`, `DRIVER_*`. **`SHELL_ENABLE` has moved (2026-11-14)**: its value comes from the
  Kconfig `ARKRTOS_USE_SHELL`, and `arkrtos_features.h` makes it an alias
  (`#ifndef SHELL_ENABLE / #define SHELL_ENABLE ARKRTOS_USE_SHELL`) while whole-file gating still
  recognises `SHELL_ENABLE`. Only the shell's resource constants (device name, task priority, stack
  size) stay here.
- Knocked-on costs must be counted too: changing `IMAGE_POOL_SECTOR` shifts the pool base upward and
  invalidates both the old device config area and every installed image (the measured account of
  F427 going 128K → 256K is recorded in the comments).
- Apps and drivers are forbidden to include this header; layout may only be fetched at runtime through
  SVC `0x18`.

### 2.2 Kconfig chain → `kernelsrc/include/arkrtos_autoconf.h` (generated)

- Inputs: root `Kconfig` + `config/kconfig/{Kconfig.capacity,Kconfig.features,Kconfig.net,Kconfig.posix}`
  + `config/arkrtos_defconfig`; output: `arkrtos_autoconf.h` (committed so a clone can build).
- `tools/kconfig/genconfig.py --check` is the `config-generated` gate: hand-editing the output, or
  changing Kconfig/defconfig without regenerating, turns it red.
- Every macro in the output is wrapped in `#ifndef`, so board configuration and command-line `-D`
  can still override it technically. That is how "behaviour unchanged when Kconfig is not used" is
  implemented, not an accident; but **feature macros in project files were zeroed on 2026-11-14**, so
  values should come only from defconfig (see §8 of [Kconfig配置系统](Kconfig配置系统.md)).
- GCC projects do not use this committed shared header: each build generates a per-build header under
  `build/kconfig/` and puts its `-I` first to shadow it ⇒ two projects on the same board may keep two
  different configurations side by side.
- It carries 88 `ARKRTOS_*` symbols, of which 53 correspond to the feature gates in
  `arkrtos_features.h`, guaranteed by the `features-switches` gate ("not one missing").

### 2.3 `kernelsrc/include/arkrtos_features.h` — the optional layer

- Answers exactly one question: **which features does this build want**. 53 `#ifndef ARKRTOS_USE_*`
  (including a few knobs without the `USE_` prefix, such as `ARKRTOS_MINI_MAX`,
  `ARKRTOS_TICKLESS_MAX_TICKS`).
- Defaults always live inside `#ifndef` and may be overridden by the board/project; when off the code
  either leaves the build entirely or has an explicit stub, never a link error. Dependencies between
  switches are reported explicitly with `#error`.
- The three capability switches (`ARKRTOS_USE_FPU / _MPU / _PRIV`) **are not here**; they belong to
  the capability layer and stay in `arkrtos_config.h` and the board configuration.

### 2.4 `kernelsrc/include/arkrtos_config.h` — capability fallbacks + numeric parameters

- 32 `#ifndef ARKRTOS_*` parameters: capability fallbacks (FPU/MPU/PRIV), MPU peripheral and external
  RAM windows, tick period, event/semaphore/mutex/POSIX waiter counts, device table, memory pool,
  message queue, condition variable, stream buffer, timers, fault records, time slice, stack bottom
  marker.
- It carries only "parameters", never addresses: "task table capacity" moved to the partition header,
  "shared memory address" was removed, and "system clock" now recognises only CMSIS
  `SystemCoreClock` (`ARKRTOS_SYSTEM_CLOCK_HZ` is a deliberately deleted dead macro; the comment
  records that it once disagreed with the silicon).
- Derived macros (such as `ARKRTOS_MS_TO_TICK`) are not wrapped in `#ifndef` — they are not
  configuration items.

### 2.5 `kernelsrc/include/arkrtos_def.h` — constant contract across the boundary

- Handle flags (`EVENT/DEV/SEM/MTX/MQ/TIMER/COND/SBUF`) and masks; SVC call numbers (`0x10`…`0x20`);
  sync return codes (`OK/PARAM/TIMEOUT/DELETED/WOULDBLOCK`); wake reasons (`NORMAL/TIMEOUT/
  OBJ_DELETED/HANDOFF`).
- These constants are shared by kernel and SDK, so changing a value means changing the ABI: both sides
  must change together, and old Apps would be misinterpreted by the new kernel.
- Semantics such as "timeout must return a negative value" and "when an object is deleted, waiters
  must receive `OBJ_DELETED`" are written in the comments; read
  [同步原语与令牌守恒.md](同步原语与令牌守恒.md) before changing anything.

### 2.6 `kernelsrc/include/arkrtos_layout_def.h` — persistent records of the CONFIG area

- Defines the identity, geometry, validation result codes and structures of the device configuration
  record; the record lives in the CONFIG area (one physical erase unit between kernel and image
  pool), written by the host tool `tools/arkrtos_cfg.py` and read by the kernel at boot.
- Division of labour with the partition header is "same values, different header": values such as
  reclaim mode and slot-table enumeration are defined in both, because this header must serve code
  that **does not include the partition header** (host tools, driver side). It includes only
  `types.h`.
- Of the runtime knobs only `log_level`, `fault_restart_max`, `boot_delay_ms` and the `RAW_ALLOW` bit
  of `flags` are actually read by the kernel; any other field written non-zero is **refused**
  (`ARKRTOS_CFG_ERR_NOT_IMPL`), not silently ignored. The reasons (no IWDG port layer / the kernel
  holds no heap / no anonymous stack pool) are written out in the comments, one by one.

### 2.7 `kernelsrc/include/arkrtos_cfg.h` — task table and boot load

- Declares the global task table `arkrtos_task_table[ARKRTOS_TASK_MAX_NUM]`, `arkrtos_task_count`,
  `arkrtos_cfg_load()`, `arkrtos_task_stack_init()`, and `arkrtos_task_stack_fill()` when
  `ARKRTOS_USE_STACK_USAGE=1`.
- Capacity still comes from the partition header (via `arkrtos_config.h`); this header defines no
  numeric value.

## 3. Five rules

1. **One switch belongs to one layer**: capability (board) / optional (`features.h`) / existing
   configuration (partition header). Giving one capability two names eventually produces "looks off
   but is actually on".
2. **Write the address once**: only in the partition header. After changing it, the `.sct` is
   regenerated by the generator, never hand-edited.
3. **Never hand-edit generated files**: `arkrtos_autoconf.h`, each board's `arkrtos_dt.c` and `.sct`
   are outputs; the first two are committed but must be produced by the generator, `.sct` is
   explicitly not committed (the `sct-not-tracked` gate watches it).
4. **App/SDK stay layout-agnostic**: layout only through SVC `0x18`, no partition-header include at
   compile time.
5. **Default off = zero change**: a new switch defaulting off must leave size and behaviour
   byte-identical to before it existed; the "compiled-in profile" must prove it really got in.

The complete checklist for adding a switch is in §"新增一个开关的清单" of [功能开关.md](功能开关.md).

## 4. Who watches these rules

| Gate (`tools/ci_gate.py`) | What it watches | Red means |
|---|---|---|
| `config-generated` | whether `autoconf.h` equals the current output of "Kconfig + defconfig" | the output was hand-edited, or an input changed without regenerating |
| `features-switches` | whether every gate in `arkrtos_features.h` has a same-named Kconfig `config` | the new switch can only be changed by `-D` and is invisible in menuconfig |
| `no-app-partition-include` | whether the App/SDK side includes the partition header | layout coupling at compile time; every new board would need Apps rebuilt |
| `layout-check` / `sct-not-tracked` | whether the partition header overlaps or overflows itself; whether a `.sct` was committed by mistake | the layout is computed wrong, or someone committed an output |
| `doc-index` | whether this page is listed in `docs/README.md` | a new document that nobody can find |

`doc-index` applies to this page too: a new or renamed page must be added to `docs/README.md`.

## 5. The three complete command sequences

```bash
# A. change a capacity: edit defconfig (or menuconfig), then regenerate
env -u PYTHONHOME -u PYTHONPATH py -3 tools/kconfig/menuconfig.py
env -u PYTHONHOME -u PYTHONPATH py -3 tools/kconfig/genconfig.py \
    --defconfig config/arkrtos_defconfig \
    --out kernelsrc/include/arkrtos_autoconf.h
env -u PYTHONHOME -u PYTHONPATH py -3 tools/kconfig/genconfig.py --list   # verify the values

# B. change layout: touch only sections 1 and 2 of the partition header, then check (.sct generation goes through each project's own build)
env -u PYTHONHOME -u PYTHONPATH py -3 tools/gen_scatter.py --check
env -u PYTHONHOME -u PYTHONPATH py -3 tools/gen_scatter.py --header config/stm32h743/arkrtos_partition.h --check

# C. change a capability: edit board/<chip>/arkrtos_board_config.h, then rebuild that board's project

# wrap up: full gate (including the Keil build and every host gate)
env -u PYTHONHOME -u PYTHONPATH py -3 tools/ci_gate.py
```

## 6. Common symptom → landing point

| Symptom | Look first at |
|---|---|
| `macro redefined` / a board override does not take effect | whether that macro in `arkrtos_config.h` is wrapped in `#ifndef`; whether the board configuration is really included first |
| defconfig changed but the board behaves the same | whether `autoconf.h` was regenerated; whether the project overrides it again with `-D` |
| a switch is missing from menuconfig | it exists only in `features.h` or the partition header and has no Kconfig `config` (`features-switches` reports it) |
| App build cannot find `arkrtos_partition.h` | this is **correct**: the App side must not include it, layout goes through SVC `0x18` |
| an image will not install / an old version starts | the pool base or pool granularity in the partition header changed, so the config area and installed images must be rewritten/reinstalled |
| a written config record is not recognised by the kernel | of the runtime knobs in `layout_def.h` only those four fields are accepted; other non-zero values are refused with `ARKRTOS_CFG_ERR_NOT_IMPL` |

- Every count on this page (53 gates, 32 `config.h` parameters, 95 partition-header macros, 87

  confirmed line by line against the sources.
