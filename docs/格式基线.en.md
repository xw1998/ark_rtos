# Format Baseline: four rules a machine can judge

> Condensed English edition. The Chinese page (格式基线.md) is normative: every number below is copied from it as of 2026-11-18, but if the two disagree, the Chinese page wins. This page adds no new claim and no new measurement.

In one line: even without clang-format there can be a format baseline that **really goes red** — judge only four rules that are pure bytes and need no re-layout; everything else is left to `.editorconfig` as an editor convention.

## 1. Why only four

The old debt was "no `.clang-format`, no `.editorconfig`, no pre-commit hook; style depends entirely on people". Copying an off-the-shelf answer runs into two hard obstacles here:

1. **This machine has no clang-format and no network** (cannot install it).
2. The repository **mixes UTF-8 and GBK** (99 files in `kernelsrc/src` + `include`: 77 UTF-8 / 22 GBK). Any "reformat the whole file" tool will happily corrupt GBK bytes, directly conflicting with the rule "GBK goes through byte-level patches, transcoding is forbidden".

So nothing is formatted here; only four rules are pinned that **need neither code comprehension nor re-layout**:

| ID | Rule | Criterion |
|---|---|---|
| F1 | no tab characters in `.c/.h` | no `0x09` inside a line |
| F2 | no trailing whitespace | after stripping the trailing `\r`, the line must not end in space or tab |
| F3 | the file ends with a newline | the last byte is `\n` |
| F4 | no UTF-8 BOM | the start is not `EF BB BF` |

All four are pure byte tests: no decoding, no transcoding, no touching of line-ending style, so they hold for the 22 old GBK files as well; fixing a violation deletes a few bytes and never rewrites a whole file.

**Deliberately out of scope** (write it down so nobody thinks "formatting is settled now"):

* Line-ending style (CRLF / LF) is not judged here — that is the `encoding` / `mixed-eol` items of `tools/ci_gate.py`, whose convention is "**no mixing inside one file**", not "the whole repo uses one style".
* Indent width (4 spaces) is only an `.editorconfig` editor convention, with no gate: there is no formatter here that can safely re-layout GBK files, so judging it could only go red without being fixable.
* Long lines (>120 columns) are editor hints only, not a criterion: 26 files of in-house code exceed 120 columns, mostly string tables and comments; putting that in the gate would force people to truncate readable text just to pass.

## 2. What is judged, what is exempt

Judged: committed `.c/.h` under `kernelsrc/` `board/` `config/` `example/`, plus `.s/.S` (assembly is subject only to F2/F3/F4; F1 is exempt because tabs are the column-alignment convention in `kernelsrc/port/arm/*/arkrtos_context.S`).

Exempt (part of the criterion, not a patch):

```
kernelsrc/components/lwip/            third-party
kernelsrc/components/cm_backtrace/    third-party
kernelsrc/components/nr_micro_shell/  third-party
kernelsrc/components/arkc/            vendored (tools/sync_arkc.py goes red on a single byte)
kernelsrc/components/arkvim/          vendored
kernelsrc/components/ark_softbus/     vendored (tools/sync_ark_softbus.py)
kernelsrc/fs/littlefs/                third-party
docs/.gen_utf8/                        generated utf8 copies
/Drivers/ /CMSIS/ /Middlewares/ /RTE/ /ARKRTOS_TEST/   ST official project trees
```

Whitespace in those trees belongs to upstream; editing it just creates the next sync conflict.

## 3. How to run

```bash
py -3 tools/format_gate.py            # self-check first, then scan the repo; 0 = all pass
py -3 tools/format_gate.py --list 40  # list at most 40 violations
py -3 tools/format_gate.py --selfcheck
```

It is wired into `ci_gate` (the `format` item; `ci_gate` went from 44 to **45** items; `sec-crc` made it **46** on 2026-11-18, and `analyzer` landed the same day bringing it to **47**), so `py -3 tools/ci_gate.py` runs it too.

**The self-check (mutation self-check) is half of this gate**: six poisoned temporary files hit F1/F2/F3/F4 respectively, one clean control, one assembly control (tabs must be allowed), plus an exemption-table assertion (`kernelsrc/components/lwip/src/core/tcp.c` must be judged exempt, `kernelsrc/src/arkrtos_task.c` must not be). Any mismatch → exit code 2, `FORMAT-GATE selfcheck FAIL`, and in that case it **never reports "0 violations"**. The reason is plain: a wrong directory, a wrong suffix, an over-wide exemption table would all leave a gate that only prints a permanent green.

## 4. The first real thing it caught: 1143 lines of `\r\r\n`

The first scan (2026-11-17) reported **2 files, 1144 occurrences** of trailing whitespace, all of the same shape: the line ends in `\r\r\n` (one CR too many), not in a space.

| File | Lines | Position |
|---|---|---|
| `kernelsrc/src/arkrtos_task.c` | 1143 | lines 555–2029 |
| `kernelsrc/include/arkrtos_shell.h` | 1 | line 43 |

### 4.1 It is not just "looks dirty", it broke `__LINE__`

The extra CR counts as **a newline** to the compiler. So `__LINE__` shifts from line 555 onward by exactly the number of `\r\r\n` lines seen before it. Evidence (same function, same address, both trees built with the same flags):

```
$ loongarch64-newlib-elf-objdump -d --start-address=0x216be0 --stop-address=0x216bf8 ...
# before (HEAD)  216be8: 03aab? -> lu12i.w $r6,1 / ori $r6,$r6,0x2ab   => line = 0x12ab = 4779
# after (worktree)216be4:              ori     $r6,$r0,0xe34            => line = 0x0e34 = 3636
```

4779 − 3636 = **1143**, exactly the number of removed extra CRs in that file. And `arkrtos_task.c` is only 3919 lines in total, so **line 4779 does not exist in the file at all** — meaning that before the fix, every log line emitted from that file (the `line` field of `ARKRTOS_LOGI/W/E`) and every debug line table pointed at a non-existent line. The most valuable column in a log (which line) was wrong throughout that 1143-line range.

### 4.2 Fix and evidence

Pure byte operation: `raw.replace(b"\r\r\n", b"\r\n")`, asserting "bytes removed == number of hits" + "both versions identical byte-for-byte once all CRs are removed" + "newline count unchanged" + "decoded content unchanged (GBK is still GBK)".

| Reading | Value |
|---|---|
| Lines changed | 3919 → 3919 (`git diff --numstat`: 1146 / 1146, plus 1 / 1 for `arkrtos_shell.h`) |
| Default-profile size | `text 367264 / data 440 / bss 767508` (identical before and after) |
| Default-profile image sha256 | HEAD tree `3a6c4ba7d84d1b0be333e3e2dd54e0f228a5f00e5ea544bc31af535c4da1c3a0` → after `8f71a10f8684f61470aa820710469284076593f8a8634f31d872b8e22476a738` |
| Size of the difference | **58 bytes**, concentrated in the `line` constant of one `log_emit` inside `arkrtos_task_kill_internal` plus 4 adjacent bytes |
| QEMU LA64 run | `help` / `info` / `sched` (consistent) / `utest run` (0 failed) all pass |

**This is not "zero change"**: the image really changed by 58 bytes, and what changed is the `__LINE__` constant itself — that is the content of the fix, not a side effect. Sizes are unchanged digit for digit, behaviour paths are unchanged, and the only run-time difference is the log line numbers (from "a non-existent line" to "the real line").

### 4.3 Two `.gitattributes` exceptions pinned along the way

These two files are **the only two whose index blob is CRLF** (the other 2093 `.c/.h` blobs are LF and check out as CRLF because `core.autocrlf=true`). Without handling, `git add` would rewrite them entirely as LF — deleting 3919 lines and adding 3919 lines, hiding the real change (removing 1143 CRs). So `.gitattributes` gives them `-text`:

```
kernelsrc/src/arkrtos_task.c      -text
kernelsrc/include/arkrtos_shell.h -text
```

`.gitattributes` **deliberately does not** write `* text=auto` or any `eol=`: mixed CRLF/LF is intentional in this repository (the old GBK files are LF in the worktree), and any tree-wide `eol=` rule would rewrite half the files and produce tens of thousands of unreviewable diff lines. "No mixed line endings inside one file" is enforced by the `mixed-eol` item of `ci_gate`.

## 5. What `.editorconfig` says

`.editorconfig` declares **editor behaviour**: 4-space indent, strip trailing whitespace, add a final newline, hint at 120 columns; `*.{s,S}` and `Makefile` / `*.mk` use tabs (tabs are syntax there); `*.md` turns off "strip trailing whitespace" (two trailing spaces are a hard break); `*.{yml,yaml,json}` use two spaces.

It does not write `charset`: after 2026-11-18 in-house sources are all UTF-8 (the `encoding` item of `ci_gate` accepts UTF-8 only), but vendored trees such as `kernelsrc/components/` may still keep another encoding to stay with upstream, and a hard-coded `charset = utf-8` would tempt editors to change them — the single worst thing for this project. Encoding is judged by the `encoding` item of `ci_gate`: in-house sources UTF-8 only, vendored trees accept both.

## 6. Order for adding a new rule

1. first write the criterion plus a **poisoned mutation self-check** in `tools/format_gate.py`;
2. run the whole repo and confirm the violation count is one you are willing to fix (otherwise clean to 0 first — never let a gate go red the moment it lands);
3. only then write it into `.editorconfig` and the table on this page;
4. after `git add`, run `py -3 tools/ci_gate.py` (47 items).

The order cannot be reversed: writing docs before criteria puts you back to "style depends on people".

## 7. Boundaries (what must not be read into it)

* Not "formatting is settled": only four rules; indent width, long lines, comment style and naming are still unmanaged.
* Not "static analysis": that is `warn_gate.py` (`-Wall -Wextra -Wshadow`, the compiler-semantics tier) and `analyzer_gate.py` (GCC 10 `-fanalyzer`, path-sensitive analysis); the two cover different segments and never replace each other.
* It does not claim "GBK files have been formatted": F1–F4 change a few bytes only.
* Whitespace habits of assembly, Makefiles and markdown are outside this gate's criteria.
