# 设备树

Ark RTOS 用一份设备树描述"这块板子上有什么"。它和分区头分工明确：

* **设备树**说硬件事实——哪个 USART 在什么地址、NOR 挂在哪个 SPI 上、板上有几颗
  灯。这些是芯片/板子决定的，不随固件布局变。
* **分区头**（`config/arkrtos_partition.h`）说固件布局——槽位、池、地址只在那一处
  定义。

设备树由 `tools/dts/dtc_lite.py` 编译成一张纯 C 的平表，运行期用一组查询 API 访问，
不需要动态内存、不解析字符串、不碰硬件。

## 1. 为什么是"子集"而不是完整 dtc

MCU 上只需要一件事：驱动按 `compatible` 找到节点的寄存器窗口和几个属性。没有 MMU、
没有地址翻译、没有中断控制器层级。所以 `dtc_lite` 只支持表达这些所需的语法，
**遇到不认识的指令一律报错**，绝不静默产出一棵空树——一个拼错的属性名应该立刻
失败，而不是等到板上"这个驱动怎么没绑上"。

支持的语法：

```
/dts-v1/;                       版本标记（接受并忽略）
/include/ "file"  或 #include "file"   包含
/ { ... };                      根节点
name[@unit] { ... };            节点
label: name { ... };            带标签的节点
&label { ... };                 overlay：往已有节点合并属性
/delete-node/ name;             删除子节点
/delete-property/ name;         删除属性
prop = "str", "str2";           字符串属性
prop = <0x1234 5 &other>;       单元属性（&ref 解析成 phandle）
prop = [00 11 22];              byte string 属性
/memreserve/ ...                接受并忽略
```

## 2. 目录布局

```
dts/stm32f4.dtsi               # SoC 共有部分：cpus、usart1-3、spi1-2、gpioa-e、iwdg
dts/stm32f427.dts              # 板：model、chosen、leds、overlay 使能外设、NOR
dts/stm32f401.dts              # 另一块板
kernelsrc/include/arkrtos_dt.h # 手写的稳定查询 API
board/<chip>/arkrtos_dt.c      # 生成产物（入库）
tools/dts/dtc_lite.py          # DTS 子集编译器 + C 生成器
tools/dts/test_dt.c            # 主机自测（断言 API 的回答）
tools/dts/host/                # 主机编译用类型垫片
```

`dtsi` 里每个外设默认 `status = "disabled"`，板级文件用 `&label { status = "okay"; }`
把它打开。只有"打开"的设备会被 `arkrtos_dt_find()` 返回。

## 3. 查询 API

```c
uint32 arkrtos_dt_count(void);
const arkrtos_dt_node_t *arkrtos_dt_node(uint32 idx);
const arkrtos_dt_node_t *arkrtos_dt_find(const char *compatible);
const arkrtos_dt_node_t *arkrtos_dt_find_next(const char *compatible,
                                              const arkrtos_dt_node_t *from);
const char *arkrtos_dt_model(void);
const arkrtos_dt_prop_t *arkrtos_dt_prop(const arkrtos_dt_node_t *node, const char *name);
int32 arkrtos_dt_prop_u32(const arkrtos_dt_node_t *node, const char *name,
                          uint32 idx, uint32 *out);
const char *arkrtos_dt_prop_str(const arkrtos_dt_node_t *node, const char *name);
int arkrtos_dt_str_eq(const char *a, const char *b);
```

约定：

* `is_device` 当节点带 `compatible` 时为 1；
* `arkrtos_dt_find*` **只返回已使能的设备**（status 缺省或 `okay`），把 disabled
  的节点排除在外；
* 找不到就是 0 / -1，不猜一个"看起来像"的结果。

## 4. 生成与校验

```bash
# 生成某块板的数据文件
py -3 tools/dts/dtc_lite.py --dts dts/stm32f427.dts --out board/stm32f427/arkrtos_dt.c

# 只看树结构，不生成代码
py -3 tools/dts/dtc_lite.py --dts dts/stm32f427.dts --dump

# 校验入库的 .c 是否与 .dts 一致（CI 用）
py -3 tools/dts/dtc_lite.py --dts dts/stm32f427.dts \
      --out board/stm32f427/arkrtos_dt.c --check

# 主机自测：编译并运行生成的表，验证 API 回答和 DTS 说的一致
py -3 tools/dts/test_dt.py
```

生成的 `board/<chip>/arkrtos_dt.c` 会随内核一起编译；它引用 `arkrtos_dt.h` 里的
类型和 API 声明。
