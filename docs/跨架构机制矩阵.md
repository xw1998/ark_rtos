# 三大机制跨架构矩阵：遗言 / 无缝衔接 / 实时性

[English edition](跨架构机制矩阵.en.md)（condensed；中文页 normative，不新增主张与读数）

本文只回答一个问题：**遗言、无缝衔接、实时性这三条机制，在每一类硬件上到底到了哪一步。**
每一格都分成三种状态，不允许混着写：

| 标记 | 含义 |
|---|---|
| **真机 / QEMU 读数** | 有串口读数或上板记录，行尾给出可核对的数字与提交号 |
| **编译面** | 编得过、门禁覆盖，但没有任何运行读数 |
| **编译期拒绝** | 打开开关即 `#error`，不是"没测过"而是"没实现" |

没有一个格子写"支持"而不给证据。没证据的格写"未验证"。

## 1. 总表

| 机制 | Cortex-M3 / M7（MPU） | Cortex-M4（MPU） | RV32IMAC（PMP） | LA64（MMU / 页表） | LA32（无运行载体） |
|---|---|---|---|---|---|
| **遗言**（`ARKRTOS_HW_SAFE`） | 机制与架构无关；**M7 有 `board/stm32h743` 与 `example/stm32h743/kernel/ARKRTOS_TEST/GCC`（Makefile 工程，无 Keil 工程），但默认 `ARKRTOS_HW_SAFE=0` 未启用，无读数；M3 无板级工程** | **真机全路径**：`devs=3 owners=6 neutralized=6 last_owner=12`（`c021168`）；通道拆分、崩溃上限跨复位、驱动回调通道三组读数 | **QEMU 台账 + 用例回调**：`devs=0 owners=2 neutralized=0`、`[PASS] hwsafe.deadman` | **QEMU 台账**：`owners=2 neutralized=8 last_owner=7`（连续 10 次 `exec` 后）；`devs=0` | 编译面（板级置 1），无运行载体 |
| **无缝衔接**（`ARKRTOS_USE_TASK_SWAP`） | **编译面**（`-mcpu=cortex-m3` / `cortex-m7` 各编过；M7 的 H743 工程默认关档，无板读数） | **真机**：`mini swap` / `app swap` / 反向切回三项通过；落地延迟 **108 / 233 / 58 ms** | **QEMU 读数**：内核自检 `swap: v1=7 -> 7  v2=100` / `swap: PASS`，5/5 次；帧改写按 `a0..a7` + `mepc` | **QEMU 读数**：同款自检 3/3 次 `PASS`；帧改写按 `a0..a7` + `ERA` | **编译期拒绝**（`#error`，无运行载体） |
| **实时性：结构**（节拍 / 优先级 / 关中断） | 可用（与 M4 同一套内核路径） | **真机读数**：`switch` 744 cyc = 7.75 µs；MPU 300 cyc = 3.1 µs；`tick.isr` 6.3 µs avg / 71.6 µs max | QEMU 跑通（CLINT 节拍 / PMP 窗口） | QEMU 跑通（分页 + PLV 用户态） | 无载体 |
| **实时性：仪表**（`ARKRTOS_USE_RTSTAT`） | 编译器面；DWT 硬件存在，M7 的 H743 工程默认 `ARKRTOS_USE_RTSTAT=0`，无板读数 | **完整读数**（见 §3.3 五张表） | **不可用**：`arkrtos_port_cyccnt_init()` 返回 `-1`，shell 如实报不可用 | **不可用**：同上，LA64 没有周期级计数器 | — |

四列硬件的"有 MPU / 无 MPU"落在同一张表里：M3/M4/M7 的 MPU 可以关（关掉后隔离退化为无，见 [实时性与最坏延迟](实时性与最坏延迟.md) §4.2 的 `PRIV + MPU 关` 一档，413 cyc = 4.3 µs）；RV32 的保护由 PMP 提供；LA64 由页表 + PLV；LA32 有分页硬件但没有能跑的载体。

## 2. 遗言：机制在每一档走到哪里

遗言（App 崩溃时把硬件带回安全态）与指令集无关：内核按任务记一张设备所有权台账，任务死亡（自退 / 被杀 / 故障恢复）时由内核执行"中和"回调。它需要的东西只有三样——设备注册表、任务终止路径、一次能跑回调的栈。

因此"能不能用"不取决于架构，取决于**这块板上有没有设备登记中和回调**。三档读数正是这样分开的：

### 2.1 Cortex-M4 / STM32F427：真机全路径

提交 `c021168`，两次独立新装复现：

```
hwsafe: enabled, devs=3 owners=6 neutralized=6 (will=3 cb=0 none=3 fail=0 handover=0) last_owner=12
```

同一镜像的阶段 2（`HWSAFE_DEMO 1.0.1`）把通道拆开：`will=1 cb=2 none=3 fail=0 handover=0`，
三条崩溃路径各自计数；崩溃上限 `CRASH:3006 slot N disabled: crash-limit, 3 consecutive faults`
在 `reboot` 之后仍保持。详见 [App崩溃硬件安全与遗言机制](App崩溃硬件安全与遗言机制.md)。

### 2.2 RV32IMAC 与 LA64 / QEMU：台账工作，但没有设备回调

RV32：

```
hwsafe: enabled, devs=0 owners=2 neutralized=0
[PASS] hwsafe.deadman devs=0 owners=2 will/cb=0/0
```

LA64 同款（owner 号不同：3 / 6）。另有一次连续 10 次 `exec` 的末态：

```
hwsafe: enabled, devs=0 owners=2 neutralized=8 ... last_owner=7
```

`owners=2` 是内核自己认领控制台设备后留下的真台账；`neutralized=8` 是 11 次任务自杀里被正常中和的次数。
`devs=0` 是实情：这两块 QEMU 板上没有驱动登记"安全态回调"，所以整机层面 `run_pending()` 无事可做。
能证明的是**机制按契约工作**——UTEST 里自带回调时，`run_pending()` 返回 1、参数对得上、重复调用返回 0（幂等）、
`path_counts` 的 `cb` 恰好 +1；release 之后死亡不再触发。

### 2.3 没有读数的两档

- **Cortex-M3 / M7**：M7 有 `board/stm32h743` 与 `example/stm32h743/kernel/ARKRTOS_TEST/GCC`
  （Makefile 工程，不是 Keil 工程），但板级配置未定义 `ARKRTOS_HW_SAFE`（默认 0），这一档没有启用，
  因而没有读数；M3 没有任何板级工程，只有 `-mcpu=cortex-m3` 级编译面。两者都不写"支持"。
- **LA32**：`board/la32_generic` 把 `ARKRTOS_HW_SAFE` 置 1，但没有 LA32 的运行载体（见 §4），
  因此只有编译面。这一档还留着一条实测教训：LA64 上曾因定时器任务栈少一帧，把 `g_hwsafe_dev_n`
  写成 trace 返回地址，进而让查表循环走到未映射地址（[MMU进程模型与ELF装载](MMU进程模型与ELF装载.md) §6）。
- **QEMU MPS2-AN386（M4）**：板级显式 `ARKRTOS_HW_SAFE=0`，这一档不启用，不算读数。

## 3. 无缝衔接：ARM 有真机读数，RV32 / LA64 有 QEMU 读数

### 3.1 帧形状下沉到端口层

`arkrtos_task_swap_take()` 做四步：整块把旧 RAM 拷到新 RAM、把新块里的那一帧改写成
"新镜像入口的第一行"、让本次异常返回改用新块里的那一帧、TCB 窗口与保护跟上。
前两步完全依赖帧的形状，所以 2026-11-20 起这部分下沉到端口层的四个函数，
内核侧不再出现任何寄存器名字：

| 端口函数 | Cortex-M3 / M4 / M7 | RV32IMAC | LA64 |
|---|---|---|---|
| `arkrtos_port_swap_frame_ok()` | `xPSR` 的 Thumb 位为 1、`IPSR == 0` | `mepc != 0` 且 2 字节对齐、`mstatus.MPP ∈ {U, M}` | `ERA != 0` 且 4 字节对齐、`PRMD.PPLV ∈ {0, 3}` |
| `arkrtos_port_swap_frame_bytes()` | 32（8 字基本帧） | 144（36 字） | 256（32 个 64 位字） |
| `arkrtos_port_swap_rewrite()` | `R0-R3/R12/LR = 0`、`PC = entry & ~1`、`xPSR = 0x01000000` | `a0..a7 = 0`、`ra = 0`、`sp = 帧尾`、`mepc = entry & ~1`、`mstatus` 只留 MPP 并置 MPIE | `a0..a7 = 0`、`ra = 0`、`sp = 帧尾`、`ERA = entry`、`PRMD` 保留 PPLV 并置 PIE |
| `arkrtos_port_swap_activate()` | `arkrtos_port_set_psp(新帧)`（异常返回从 PSP 弹帧） | 记进端口层静态变量，由 `riscv_trap_c` 在 SVC 返回后换掉帧指针 | 同左，由 `la_trap_c` 消费 |

`take()` 成功后还会把 `p_task->stack_ptr` 指向新帧：RISC-V / LoongArch 的下一次切换是从
trap C 的返回值取帧的，不同步的话，"落地"与"下一次切换"之间 TCB 里还指着马上就要被
还回去的旧块。

RV32 那一格有一条只有实跑才发现的判据：**对齐必须按 2 字节判，不是 4 字节**。本 port 编的是
RV32**IMAC**，C 扩展让 `ecall`（本身 32 位）可以落在 2 mod 4 的地址上；按 4 字节判会把它判成
"坏帧"，`swap` 表现为随机 FAIL（`v1` 一直涨、`v2` 一直是 0），且只与链接后的指令落点有关
（实测 `mepc=0x8002B80E`）。`rewrite()` 里的 `entry & ~1u` 与它同源。

`arkrtos_features.h` 的架构闸门随之收窄：允许 Cortex-M3/M4/M7、RV32IMAC（arch id `0x0201`）、
LA64（`0x0302`）；RV64GC 与 LA32 仍然 `#error`。默认档（`0`）不受影响：
不编译、不加符号、体积与行为不变。

### 3.2 各档读数

| 硬件 | 证据 |
|---|---|
| Cortex-M4 / F427 | **真机**：`mini swap` 换块且旧块归还（`1 of 4 in use` 前后不变）、`app swap` 旧槽保留 `LOADED`、反向切回；`arm` → 落地 **108 / 233 / 58 ms**（`LOADER:2902 swap armed` → `SWAP:3327 task 4 now runs`） |
| Cortex-M3 / M7 | **编译面**：`tools/swap_syntax_gate.py` 用 `-mcpu=cortex-m3` / `cortex-m7` 各编一遍移植层 |
| RV32IMAC / LA64（QEMU） | **QEMU 读数**：内核自检 `swap` 在 RV32 上 5/5 次、LA64 上 3/3 次 `PASS`（`v1` 在切换后停住、`v2` 起来）；RV32 每次都是 `swap: v1=7 -> 7  v2=100`，LA64 的 `v1` 在 2 与 7 之间变（取决于切换落点时桩跑了几轮），`v2=100`。八次运行全程 `fault=0` |
| LA32 | **编译期拒绝**：门禁对真实交叉编译器取读数——开档必须非零退出且命中拒绝文案，关档必须 `0` |

这两档的读数来自**内核自检命令 `swap`**，不经过小程序/App 装载器：它注册一个跑在静态块 A 上的
循环桩 `v1`，等计数真的涨起来后把"换到块 B、入口 `v2`"挂上，切换落在 `v1` 自己的下一次 `wait`
里；判据只有两条——`v1` 的计数在切换后不再变化（旧镜像停住），`v2` 的计数开始上涨（新入口在跑）。
两个入口都在内核镜像里（`rom_start` 传 `CHIP_FLASH_BASE`），所以这条读数证明的是
**帧判据 + 整块搬迁 + 帧改写 + 恢复路径换帧**，**不是镜像重定位**；PIC 与装载属于
mini/app 装载器，由 ARM 上板读数覆盖，与指令集无关。

门禁同时保留一条负对照：LA32 开档必须仍被拒绝。只验"能编过"的话，删掉 `#error` 就会假绿。

同一次上板还暴露了两个必须写进结论的事实（[无缝升级-双缓冲热切换](无缝升级-双缓冲热切换.md) §5 / §9.2）：

1. **数据段不连续**：换过去之后启动桩会重跑 `.data` 初值搬运与 `.bss` 清零，探针 `bss=0 data=0x5A5AA5A5`
   在跑过 569 次迭代后掉回初值。"无缝"指的是**不重启、不写 Flash、不进调度**，不是"内存状态不丢"。
2. **心跳契约会短暂违约**：四次 `app swap` 里观测到一次 `GUARD:348 not feeding`；契约周期 1000 ms、
   看门狗 4000 ms，多数时候接得上，但不保证。

## 4. 实时性：保证来自结构，读数来自仪表

这两件事必须分开写，否则会把"没有仪表"读成"没有实时性"。

### 4.1 结构：每一档都在跑

节拍、优先级抢占、关中断临界区、PendSV/等价切换路径都在内核里，与指令集无关。
Cortex-M3/M4/M7 走 `PendSV` + `PSP`；RV32 走 `ecall` + `mret`；LA64 走 `syscall` + `ERTN`。
四档的差别只在"有没有人量过"，不在"有没有这套机制"。

### 4.2 仪表：只有 ARM 有周期级计数器

`arkrtos_port_cyccnt_init()` 的契约是"给不了就返回 -1，不要编一个粗三个数量级的分辨率"：

| 架构 | 实现 | 读数 |
|---|---|---|
| Cortex-M3 / M4 / M7 | DWT `CYCCNT` | 可用（96 MHz 下一个计数 10.4 ns，约 44.7 s 回绕） |
| RV32IMAC | 明确返回 `-1` | 不可用 |
| LA64 | 明确返回 `-1`（`rdtime` 是时间基准，不是周期计数） | 不可用 |
| LA32 | `rdtime` 时间基准；无载体 | — |

`arkrtos_rt_init()` 拿到 `-1` 后把 `ready` 留在 0，所有测量项 `n = 0`，shell 如实打印不可用。
**不退回节拍计数去凑数**——那会得到一个分辨率差三个数量级的"读数"，比没有更坏。

### 4.3 M4 的真机读数（本仓库唯一完整的一组）

STM32F427VGTx，96 MHz（HSI 经 PLL），节拍 2 kHz（500 µs），`rt run 3000`：

| 量 | 读数 |
|---|---|
| `switch`（调度决策点 → 任务第一条指令） | 744 / 744 / 745 cyc = **7.75 µs**，几乎无抖动（`MDK_TRACE` 关） |
| `tick.isr` | 603 cyc avg / 6870 cyc max = 6.3 / 71.6 µs |
| `wake.lo` | 4393 cyc avg / 22074 cyc max = 45.8 / 229.9 µs |
| `jitter` | −22.7 / +22.6 µs |
| MPU 地址隔离 | ≈ 300 cyc = **3.1 µs**（423 → 723） |
| 特权切换 | ≈ 20 cyc = **0.2 µs**（744 → 723） |
| 默认档（观测全开） | `switch` 3651 cyc avg / 218.3 µs max；关掉 `MDK_TRACE` 后掉到 744 |

同一份源码三档只差板级两个宏，读数与限定条件见 [实时性与最坏延迟](实时性与最坏延迟.md) §4。

## 5. 开关与零体积

| 开关 | 默认 | 关档行为 |
|---|---|---|
| `ARKRTOS_HW_SAFE` | 0（`features.h`） | 设备 open/close 与任务终止路径与本机制引入前完全一致 |
| `ARKRTOS_USE_TASK_SWAP` | 0（Kconfig + `features.h`） | 原语、两个消费者、SVC 钩子、两条 shell 命令全部不编译；未实现的架构（RV64GC / LA32）打开即 `#error` |
| `ARKRTOS_USE_RTSTAT` | 0（Kconfig + `features.h`） | 不编测量代码；`arkrtos_rt_init()` 不存在 |

遗言在 `qemu_loongarch64` / `qemu_riscv32` / `la32_generic` 三个板级头上置 1，是为了让它在
真实载体上被编译；这不改变"关档零体积"的结论，只说明这三块板选了打开。

## 6. 门禁覆盖

| 门禁 | 覆盖什么 | 不覆盖什么 |
|---|---|---|
| `swap`（`tools/swap_syntax_gate.py`） | 开档 15 个 TU 在 armclang 下编过（m3/m4/m7）；LA64/RV32 开档**必须编过**（真实交叉编译器各跑一遍）、LA32 开档**必须仍被拒绝**、三档关档都要编过 | 换过去之后的运行行为（F427 是上板读数；RV32/LA64 是内核自检读数，不是装载器路径） |
| `rtstat` | 开档 7 个 TU 编过 | 非 ARM 上"仪表不可用"的运行时表现（代码里是 `-1` 分支） |
| `elf` / `paging` / `linux-abi` | MMU 档的装载、页表、系统调用 ABI | 遗言 / 无缝衔接在 MMU 档的行为 |
| `doc-index` | 本页在中英两个索引里各出现一次 | — |

遗言没有独立的门禁项：它的证据全部来自板级配置与上板/UTEST 读数，不在编译面能判。

## 7. 边界

1. **本页不声明"三机制在所有架构可用"。** 它声明的是：遗言在所有有载体/有编译面的架构上机制成立；
   无缝衔接在 Cortex-M 有真机读数、RV32IMAC 与 LA64 有 QEMU 读数，LA32/RV64GC 是编译期拒绝；
   实时性结构全架构成立，仪表只有 ARM 有。
2. **"编译期拒绝"不是"未验证"。** 前者是设计选择（不给错答案），后者是欠账。两者在总表里分开标。
3. **QEMU 算上板，不等于真机。** 本页把 §2.2 与 §3.2 的读数按来源标成 QEMU；`devs=0` 与
   "入口都在内核镜像里"两条边界同时写出。
4. **M3/M7 的空白不是架构限制。** M7 侧的板级工程（H743，GCC/Makefile）已在仓库里，缺的是打开
   `ARKRTOS_HW_SAFE` / `ARKRTOS_USE_RTSTAT` 后的一次烧录读数；M3 侧缺板级工程与烧录。两者缺的都不是内核路径。
5. **RV32 / LA64 的帧改写已完成，判据是 QEMU 读数**：RV32 改 `a0..`、`sp`、`mepc`、`mstatus`，
   LA64 改 `a0..`、`sp`、`ERA`、`PRMD`，两档各有 5/5 与 3/3 次 `swap: PASS`。仍欠的是**真机**
   （QEMU 不是硅）与 **ARM 上 mini/app 装载器路径的等价读数**（RV32/LA64 的读数来自内核自检）。
6. **每一格的级别是台账里的一行，不是散文。** `tools/evidence_levels.tsv` 逐条写明
   主张 / 架构 / 级别（L0–L3）/ 载体 / 出处提交号，由 `tools/evidence_gate.py`（CI 项
   `evidence-levels`）机械校验：L2 的载体必须是存在的 `board/qemu_*`、L3 不能是 `qemu_*`、
   证据提交号必须能在 git 历史里查到、L3 行数冻结（当前 4 行，全部 F427）。分级定义与
   「QEMU 为什么升不成 L3」见 [验证载体分级](验证载体分级.md)。
