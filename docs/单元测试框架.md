# Ark RTOS 板端单元测试框架（utest）

## 一句话

内核里那些"用错了才出事"的契约——信号量令牌守恒、FIFO 环形容量、事件位语义、
定时器生命周期、审计结构自洽——都被写成了板子上可以一键重跑的用例；改坏了立刻
变红，而不是等某个应用半夜崩在客户现场。

形态对齐 RT-Thread 的 utest / Zephyr 的 ztest：用例**自动注册**，断言**只记账不中断**，
运行器给出总账。

## 怎么用

在串口控制台（F427 上 USART1 @ 115200 8N1）里：

```
ark> utest list              # 列出已注册的用例
ark> utest run               # 跑全部
ark> utest run fifo_         # 只跑名字里含 "fifo_" 的（子串过滤）
```

命令返回**失败用例数**，所以脚本可以直接靠返回值判红绿：

```
ark> utest run
RUN   sem_token_flow
PASS  sem_token_flow
...
utest: 9 matched, 9 passed, 0 failed, 0 skipped; assertions 73 run / 0 failed
```

## 写一条用例

用例是普通函数，用 `UTEST_CASE(id)` 定义。展开后它是一个静态登记项 + 一个
`__attribute__((constructor))` 构造函数，所以**不需要维护任何中心清单**：
把文件加进工程，用例就自己出现在 `utest list` 里。

```c
#include "arkrtos_utest.h"
#include "arkrtos_sync.h"

UTEST_CASE(sem_token_flow)
{
    int32_t h = arkrtos_sem_create("utsem", 2);
    UTEST_REQUIRE(h >= 0);              /* 失败即 return，后面的断言不再执行 */

    UTEST_CHECK_EQ(arkrtos_sem_take(h, 0), 0);
    UTEST_CHECK_EQ(arkrtos_sem_take(h, 0), 0);
    UTEST_CHECK_EQ(arkrtos_sem_take(h, 0), -1);   /* 令牌用尽 */

    arkrtos_sem_delete(h);
}
```

### 断言宏

| 宏 | 语义 | 失败后 |
|---|---|---|
| `UTEST_CHECK(expr)` | 真值 | 记账，继续 |
| `UTEST_REQUIRE(expr)` | 真值 | 记账并 `return`（前置条件） |
| `UTEST_CHECK_EQ(a, b)` | `a == b` | 记账，继续 |
| `UTEST_CHECK_NE(a, b)` | `a != b` | 记账，继续 |
| `UTEST_CHECK_RANGE(lo, x, hi)` | `lo <= x <= hi` | 记账，继续 |
| `UTEST_FAIL(msg)` | 无条件失败 | 记账，继续 |
| `UTEST_SKIP(reason)` | 主动跳过 | 记账并 `return` |

每条断言先计数（`checks`），再判是否失败（`failed_checks`）；一条用例里失败多少条
都数得清，不会"第一条失败就把后面吞掉"。

### 汇总账（`ark_utest_summary_t`）

| 字段 | 含义 |
|---|---|
| `cases` | 实际执行的用例数 |
| `passed` / `failed` / `skipped` | 全通过 / 有失败 / 主动跳过 的用例数 |
| `checks` / `failed_checks` | 断言总条数 / 失败断言条数 |
| `matched` | 模式匹配到的用例数（含被跳过的） |
| `overflow` | 注册表溢出次数 |

## 开关

`kernelsrc/include/arkrtos_features.h` 里的 `ARKRTOS_USE_UTEST`，**默认 1**；
Kconfig 里也有同名符号（`menuconfig` → Services and components → Reliability and operations），
可改 defconfig 配置。
置 0 时框架与 shell 的 `utest` 命令都不参与编译，体积与行为零变化。

## 设计要点（都是踩过坑才这么写的）

1. **三种工具链都能自动注册。** 自动注册依赖 `__attribute__((constructor))`：
   armclang / GCC 原生支持；ARMCC 5 会把它落到 `.init_array`，
   并在 `__main → __cpp_initialize__aeabi_` 里被调用（已用 armlink 出的镜像
   反汇编核实）。若某个工具链既不认该属性、又不跑 `.init_array`，退化的表现是
   `0 case(s) registered` —— 是一个显式的空账，而不是造假通过。
2. **溢出计数，不静默丢弃。** 用例表容量固定（`ARKRTOS_UTEST_MAX_CASES`，默认 64），
   超出的登记计入 `overflow` 并报出来，绝不无声无息地少跑几条。
3. **框架不依赖 printf / shell。** 输出走可注入的汇（`ark_utest_set_output`），
   板端接到控制台，宿主机接到内存缓冲 —— 同一份核心因此能在 PC 上自测。
4. **用例一律非阻塞。** 用例跑在 shell 任务上下文，凡可能"睡"的调用一律
   `timeout == 0`，避免把控制台挂住。

## 门禁

`tools/ci_gate.py` 里的 `utest-host` 检查：用宿主 gcc 编译并运行
`tools/utest_host_selftest.c`，要求退出码 0 且打印 `HOST-SELFTEST OK`。
它证明的是**框架自身的记账**（通过/失败/跳过/断言条数/溢出/子串过滤/自动注册）
正确，跟板子无关；改了框架、记账歪了，门禁就会红。

## 宿主门禁一览（不依赖板子）

模块级的"字节搬运 / 账目算术"不必等板子：把调度器换成桩，同一份 `.c` 就能在 PC 上跑。
这几条门禁都在 `tools/ci_gate.py` 里（缺宿主编译器是 **FAIL 不是 skip**），
每一份测试文件的开头都写明了「已验证什么 / 刻意没验证什么」：

| 门禁项 | 被测模块 | 证明了什么 | 明确没证明 |
|---|---|---|---|
| `sbuf-host` | `arkrtos_sbuf.c` | 环形回绕、部分发送、长度前缀消息整条原子、丢弃后不串下一条 | 阻塞/唤醒 |
| `mempool-host` | `arkrtos_mempool.c` | 块几何与对齐校验、O(1) 分配/释放、被拒的释放不动池子 | SVC 0x20 的参数检查 |
| `mq-host` | `arkrtos_mq.c` | 槽位回绕、按声明长度收发、缓冲更小时截断但仍整条消费、满时拒绝且不覆盖、删除后句柄失效 | 阻塞/唤醒、删除时唤醒等待者 |
| `sync-host` | `arkrtos_sync.c` | 令牌守恒（取用/耗尽/0 超时/归还）、互斥锁归属（持有者重入被拒、非持有者解锁被拒）、删除后接口一律拒绝 | 阻塞/唤醒/令牌转交、优先级继承 |
| `fifo-host` | `arkrtos_fifo.c` | create 的尺寸门槛（≤ 8 直接拒且不碰缓冲，可用容量 = size−9）、写满拒绝且不覆盖、环形回绕后顺序不变、短读、len≤0 空操作、坏魔数与 NULL 句柄的两次计数（read 只计次数不丢字节）、`write_refused` 跨 FIFO 累计 | 单生产者-单消费者之外的并发；size > 65543 的 uint16 截断（已知限制）；手造 size==0 头的除零（调用方违约） |
| `fault-host` | `arkrtos_fault.c` | 空表 count 0；未写满时 0 = 最旧且顺序与写入一致；count 封顶在 `ARKRTOS_FAULT_RECORD_NUM`；写满后覆盖最旧、`0 = 总记录数 − N`；越界 index 返回 NULL；tick 逐条取值；重新 init 连游标一起归零；每条记录落在成对临界区之间 | 真实中断嵌套下的原子性（桩把临界区做成空操作，配平只说明成对）、真 HardFault 路径调用、SVC 读取的打包格式 |
| `loader-host` | `arkrtos_loader.c` | 镜像头拒绝顺序与边界（魔数/兼容号/type 越界与掩码/image_size 为 0 与回绕/entry 越界/reloc_offset 与 count 与编码版本与 payload_offset/表项对齐·越尾·升序/ram_size 为 0 与超单块上限）、重定位补丁语义（整字按 ROM·RAM 分别叠加、MOVW+MOVT 解成 32 位重编码且保留指令位、块尾切断指令表项返回表项起点且 idx 不动、`off < buf_off` 跳过但指针前进） | 装载/流式安装/Flash 擦写/池内搬移/卸载/签名/CRC/崩溃计数，以及**能否真正启动**——这些都由板端用例与 App 例程取证（`utest` / `APP_DEMO` / T10–T12），`loader-host` 本身不替代它们 |

`sync-host` 与另外三条不同的一点：它把 `arkrtos_task_get_current()` 换成**可设置的**
真实指针，所以"谁能解锁""什么算重复加锁"这类归属判定是真跑过的，不是只编过。

每条的独立入口：`py -3 tools/sbuf_host_gate.py` / `mempool_host_gate.py` /
`mq_host_gate.py` / `sync_host_gate.py` / `loader_host_gate.py` / `fifo_host_gate.py` / `fault_host_gate.py`
（`--gcc` 指定编译器，`--keep` 保留 exe 便于复跑）。

## 当前用例清单

`kernelsrc/src/arkrtos_utest_cases.c`，9 条（按 `ARKRTOS_USE_MEMPOOL/TIMER/AUDIT`
裁剪）：

| 用例 | 校验的契约 |
|---|---|
| `mempool_contract` | 固定块内存池：分配/释放循环、耗尽返回空 |
| `sem_token_flow` | 信号量令牌守恒：取满后取不到 |
| `sem_reject_bad_handle` | 坏句柄被拒，不误伤合法句柄 |
| `mtx_lock_unlock` | 互斥量加锁/解锁配对 |
| `fifo_capacity_and_order` | FIFO 环形容量与先后顺序 |
| `fifo_bad_magic_is_counted` | 坏 magic 写入被拒且计入 `bad_magic`/`bad_magic_bytes` |
| `event_set_wait_flag` | 事件组置位/等待位语义 |
| `timer_lifecycle` | 软件定时器创建/启动/停止/删除 |
| `audit_structures_consistent` | 审计结构自洽 |

F427 上板实测：**9 matched / 9 passed / 0 failed / 0 skipped，73 条断言**。
把 `ARKRTOS_USE_SBUF=1` 打进 Keil 工程的 Define 框后是 **12 matched / 12 passed，
115 条断言**（多出的正是 `sbuf_stream_contract`、`mbuf_framing_contract` 与
`sbuf_block_wake_contract`，见 [流缓冲与消息缓冲](流缓冲与消息缓冲.md) §五）。

这 12 个里只有 `sbuf_block_wake_contract` **会让出控制台**：它用一个 20 ms 的
一次性定时器回调送数据，再以 400 ms 超时阻塞等待，因此是对"用例绝不阻塞"这条
设计约束的**有意破例**。破例的前提是**自带上限**：所有超时都是毫秒级且远小于
控制台保活，即使内核唤醒路径坏了，最坏也只是这个用例 FAIL 400 ms 后回来，
不会把 shell 挂死。板上实测 40 拍 = 20.0 ms（唤醒）与 60 拍 = 30.0 ms（超时）。
