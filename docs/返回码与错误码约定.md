# 返回码与错误码约定

想知道某个内核函数失败时那个负数是什么意思，看这一页。

本页回答三件事：**名字从哪来**、**值和以前一不一样**、**哪些数不是错误码**。

## 1. 约定

内核 API 的失败返回一律是**负整数**，0 表示成功，正数表示"成功且带了信息"（如读到的字节数）。这个口径本轮没有动过，以后也不打算动。

本轮补的只是**名字**：

1. 每个模块在**自己的头文件**里定义一组 `ARKRTOS_<模块>_ERR_<原因>`，纯 `#define`，无额外依赖。
2. **每一个宏的值，逐处等于改动前那里写死的那个数字。** 不是重新设计码值，是给既有数字起名。
3. **多个名字共用 `(-1)` 是有意的**，不是漏了错值。分名的目的是让调用方和读代码的人知道"这是哪一种失败"，而不是让每种失败有不同的数。
4. **值不得单独修改。** 想区分某两种失败，是新增一个值域方案（需要动 ABI 和全部调用方），不是把某个宏从 `-1` 改成 `-3`。改一个宏的值等于悄悄改了对外契约。
5. 错误码宏放在各头文件的**功能开关之前**（`timer` / `mempool` / `softbus` 尤其注意），这样 `ARKRTOS_USE_XXX=0` 时 `#else` 分支的桩函数也能用同一套名字。

## 3. 三个名字不是错误码

这三处是**哨兵**（sentinel），调用方会拿它当分支条件，不要当失败处理：

1. **`ARKRTOS_MQ_WAIT_INFINITE`（-1）**：`remain_ms` 的"无限等待"标记。所以 `-1` 在 mq 里同时是"无限等待"和若干个失败原因——**同一个数在不同参数位置上语义不同**，靠参数位置区分，不靠值区分。
2. **`ARKRTOS_MQ_WAITER_DUP`（-2）/ `ARKRTOS_EVENT_WAITER_DUP`（-2）**：登记等待者时发现该任务已在队列里。这是"无需重复登记"的提示，不是错误。
3. **`ARKRTOS_CRASH_INDEX_NONE`（-1）**：`arkrtos_crash_mini_find()` 找不到记录时的下标哨兵，不是错误码。

同理 `ARKRTOS_EVENT_WAITER_ABSENT`（-1）表示"摘除时本来就不在队列里"，是幂等语义，通常可忽略。

## 4. 三条不得"统一"的既有契约

补名字的时候最容易犯的错是"顺手把 -1 都改成 -2"，下面三条在历史上就是这样，**改了会破坏调用方**：

1. **mq 的 send 超时是 `-1`，recv 超时是 `ARKRTOS_SYNC_ERR_TIMEOUT`（-2）。** 两侧不对称是既有契约，见 `同步原语与令牌守恒.md`。
2. **dev 注册时"名字或驱动指针为空"是 `ARKRTOS_DEV_ERR_ARG`（-2）**（第 43 行），注册重名是 `ARKRTOS_DEV_ERR_EXIST`（-2）。这两个值本轮特意保留为 -2；曾经误映射成 -1，导致 `arkrtos_dev.o` 涨 4 B、总 Code 220094→220098，是体积账抓出来的。
3. **vfs 的 `-1` 不得改成既有 `ARKRTOS_VFS_EINVAL`（-2）。** VFS 有自己的 `E*` 体系（`-2` 起），本轮新增的 `ARKRTOS_VFS_ERR_*` 全部是 -1，两者并存：`E*` 是给调用方判断的 POSIX 风格错误，`ERR_*` 是内核内部返回点的名字。

## 5. 覆盖范围（如实记账）

**本轮覆盖**：mq、event、timer、mempool、blk、dev、softbus、vfs、guard、sec、crash 共 11 个模块，163 处。

**已排除**：

- `net`：已有自己的 `ARKRTOS_NET_E*` 体系，且 `.c` 里 0 处裸 `return -N`。
- `sign`：`.c` 里 0 处裸 `return -N`（返回值只有 0/-1，且 -1 只在极少路径）。

**本轮未覆盖（下一轮再收）**：`fs`、`ptable`、`sync`、`task`、`loader`、`hwsafe`、`mini`、`installer`、`sbuf`、`rt`、`log`、`cfg`。它们多数已有部分错误码或状态枚举，需要先盘点再动，硬套一套宏反而会掩盖已有的语义差别。

## 6. 验证口径

只到"0 Error"不算验证完。本轮做了三层：

1. **值一致性脚本**：逐文件比对 `HEAD` 版本里 `return -N;` 的数字与本行宏展开后的值，收全 152 个负值宏，`real mismatch: []`。
2. **体积逐项比对**：默认档内核 Keil 构建 `Code=220094 RO-data=19198 RW-data=896 ZI-data=120852`，与 `4796ab1` 干净 worktree 的**全量重建**逐项相同（增量构建的数不可直接比，必须 `-r` 或干净 worktree）。
3. **关档语法检查**：把 `MQ/TIMER/MEMPOOL/BLK/FS/VFS/VFS_LFS/SOFTBUS/SECCHECK/MINIAPP/PROCFS/MINI/APPPACK` 全设 0，11 个模块 `arm-none-eabi-gcc -fsyntax-only` 全过，证明 `#else` 桩也能看到宏。

**验证档位**：仅编译通过 + 体积逐项相同。**本轮未上板复验**（改动只涉及名字，不涉及控制流，但按口径仍应记为未上板）。

## 7. 新增一个返回点怎么写

1. 先看那个 `return -N` 属于哪种失败。
2. 到模块头文件里找现有最贴近的 `ARKRTOS_<模块>_ERR_*`；**同义就复用，不要为每一行新建一个名字**。
3. 确实没有合适名字时，才新增一个宏，值仍写 `(-1)`（除非有历史原因必须是别的值），并写一行注释说明判据。
4. 不要为了"看起来更精细"而改值。
5. 改完跑上面第 6 节的三层验证。
