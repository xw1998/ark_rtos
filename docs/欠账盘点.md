现状约束）。限制本身的口径见 [已知限制](已知限制.md)；这页只回答"还剩什么没做、
怎么确认还欠着"。

> 规则：一条欠账只有三种结局——**做完并验证**（移进对应功能文档并在此删行）、

| 项 | 实测 | 说明 |
|---|---|---|
| `SVC_Server()` 巨型 dispatch | **已拆（2026-11-13）**：1318 行 → **58 行** dispatch 表 + 17 个 `static void svc_*(void *p_svc_ctx)` handler | 纯搬运：case 体逐行 dedent；体内"退出本 case"的 14 处 `break;` → `return;`（内层 switch 的 `break` 一个未动）。`Code` +408 B（+0.19%）、RO/RW/ZI 不变；编译 0 err / 0 warn；行级等价性已用"归一化行多重集"论证。**上板行为已复验（2026-11-13）**：`sec all` 12 checks（pass 8 / fail 0 / finding 2 / skip 2，`gates.kernel` bits=0xBF、`structures.audit` checks=34 mask=0x0、`images.headers` slots=2 bad=0）、`app install/start/stop/uninstall`（本轮 4 次装载 2 个不同镜像）、`sched` 报 `consistent (bitmap/links == task table)`、`utest run` 9/9（断言 73/0） |

核对命令（两条，都在仓库根目录跑）：

```bash
# 1) 函数长度分布：列首函数名 + 五行内找到 '{'，向后数到列首 '}' 收尾
py -3 tools/doc_audit.py funcs

# 2) 编码分布：能解成 UTF-8 就是 UTF-8，否则按 GBK
py -3 tools/doc_audit.py enc
```

口径说明：`funcs` 只认"函数名与括号在同一行"的写法，多行签名会被漏数，所以数出来
的 **25 个 >120 行**是**下界**（早前一次口径数到 19 个，差异全在这里，不是数字变了）。

## 五、优先级（按"补齐成本 / 收益"排）

1. **静态分析 + 覆盖率接进 `ci_gate`** —— 唯一能自己发现问题的欠账，也是所有其他欠账的放大器。落点：`cppcheck --enable=warning` 跑 `kernelsrc/src`（需先装工具）；宿主测试跑 gcov 并设一条"不低于当前值"的下限。
2. **远程 CI** —— 把现有 `ci_gate`（29 项）原样搬进 gitee 流水线，让门禁离开某台机器。
3. ~~拆 `SVC_Server`~~ —— **已收口（2026-11-13）**：1318 → 58 行 + 17 个 handler，纯重构，`ci_gate` 全绿、编译 0/0、`Code` +408 B；上板行为已复验（`sec all` 8 pass / 0 fail、`app` 装载启停卸载、`sched` 一致、`utest` 9/9），读数见 §三。
4. **编码统一** —— 22 个 GBK → UTF-8，单独一个提交、只转码不动逻辑；转完把 `encoding` 检查收紧为"只许 UTF-8"。
5. ~~功能欠账里挑一条真做~~ —— **mempool 的 SVC 通道已上板（2026-11-13）**，tickless 也已上板；剩余功能欠账里以太网要等 PHY 硬件，软总线两节点要第二块板。
