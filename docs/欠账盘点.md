# Ark RTOS 欠账盘点

2026-11-13 逐项核对后写成。每条都有**核对命令**、**判据**、**性质**（欠账 / 取舍 /
现状约束）。限制本身的口径见 [已知限制](已知限制.md)；这页只回答"还剩什么没做、
怎么确认还欠着"。

> 规则：一条欠账只有三种结局——**做完并验证**（移进对应功能文档并在此删行）、
> **明确取舍**（移到 [已知限制](已知限制.md) 并写理由）、**继续欠着**（留在这里，
> 带核对命令与判据）。不允许"看起来做了"就删行。

## 一、功能欠账（该做没做完 / 做了一半未验证）

| 项 | 性质 | 现状 | 核对命令 / 判据 |
|---|---|---|---|
| 真实以太网收发 | 欠账 | 板级无 PHY 驱动、无 MDIO、无 `eth_` 接口、无 RMII 引脚分配；lwIP 只跑回环 netif | `grep -ri "mdio\|rmii\|eth_" board/stm32f427/` 为空即为欠着；判据 = 一条真实链路 ping 通并抓包 |
| tickless 上板 | 欠账 | 宿主门禁 `tickless` 过（睡眠长度账 + 相位结算 + ON 档编译），板端未实测 | `env -u PYTHONHOME -u PYTHONPATH py -3 tools/ci_gate.py` 看到 `tickless` pass 只证明宿主；判据 = 板上 `rt` 在 idle 段测到 WFI 停留时长 |
| mempool 的 SVC 通道（App/驱动侧） | 欠账 | 内核侧上板，SVC 0x20 的非特权侧未上板 | 判据 = 一个 `.svcapp` 经 SVC 0x20 分配/释放并打印块地址 |
| 软总线物理线两节点 | 欠账 | 只有板内 loopback（`bus selftest` 10 段 `checks 56 failed 0`） | 判据 = 两块板（或板 + PC）走真实串口完成一次事件 + 一次远程调用 |
| 小程序正常退出走计划内交接 | 欠账 | Ark 侧未取到（nano 侧已上板验证） | 判据 = 小程序正常退出后 `hwsafe` 报 `handover=1` 且设备未被中和 |
| RISC-V / LoongArch 移植实现 | 欠账（范围外） | 只有 arch 抽象层，无 port 实现 | `ls kernelsrc/port/` 只有 arm/ 即为欠着 |
| shell 认证 | 欠账 | 缺口寄存器 SEC-G13 | 见 [安全认证准备](安全认证准备.md) §7 |
| Flash 选项字节读取通路 | 欠账 | 缺口寄存器 SEC-G14，`sec` 里对应项只能 SKIP | 同上；判据 = `sec` 该项由 SKIP 转 PASS |
| TrustZone / Cortex-M33 | 欠账（范围外） | port 只有 M3/M4/M7，全仓 `TrustZone` 零命中 | `grep -ri trustzone kernelsrc board` 为空 |

## 三、程序易读性欠账

分布本身是健康的，问题集中在少数巨型实体与三处"入口混乱"：

| 项 | 实测 | 说明 |
|---|---|---|
| `SVC_Server()` 巨型 dispatch | **已拆（2026-11-13）**：1318 行 → **58 行** dispatch 表 + 17 个 `static void svc_*(void *p_svc_ctx)` handler | 纯搬运：case 体逐行 dedent；体内"退出本 case"的 14 处 `break;` → `return;`（内层 switch 的 `break` 一个未动）。`Code` +408 B（+0.19%）、RO/RW/ZI 不变；编译 0 err / 0 warn；行级等价性已用"归一化行多重集"论证。**上板行为未复验（探针不在线）** |
| 次一级长函数 | 拆分后最长的是 `svc_file_sys` 458（`arkrtos_task.c`，原 `SVC_Server` 的 `FILE_SYS` 分支），其后 `arkrtos_mini_run` 348（`arkrtos_mini.c:256`）、`arkrtos_apppack_build` 244、`arkrtos_loader_stream_image` 212、`arkrtos_flashapp_write` 211、`arkrtos_layout_validate` 199、`arkrtos_apprun_run_ex` 195、`arkrtos_apppack_scan` 185、`arkrtos_loader_move_slot` 167、`arkrtos_guard_tick` 166 | >200 行 5 个、>120 行 25 个（`doc_audit.py funcs` 口径的下界），占 828 个函数的 3.0%，平均函数 24 行 ⇒ 不用全局重构，按需拆 |
| `kernelsrc/shell/arkrtos_shell.c` | **6132 行**单文件 | 命令注册与实现混在一起，新增命令都在这里堆 |
| 编码混用 | `kernelsrc/src` + `include` 共 99 文件：**UTF-8 77 / GBK 22** | 阻塞任何自动格式化、静态分析、跨文件搜索；转码要一次性单独提交（且与"GBK 字节级补丁"约定冲突，需明确决定） |
| 配置头并存 | 6 个：`arkrtos_cfg.h` / `arkrtos_config.h` / `arkrtos_features.h` / `arkrtos_autoconf.h` / `arkrtos_def.h` / `arkrtos_layout_def.h` | 真正的事实源是 `config/arkrtos_partition.h` + `config/kconfig/`；入口缺一页导航（[功能开关](功能开关.md) 与 [Kconfig配置系统](Kconfig配置系统.md) 各讲一半） |
| 格式基线 | 无 `.clang-format`、无 `.editorconfig`、无提交前钩子 | 风格全靠人；`ci_gate` 只查编码与行尾 |
| 注释率 | 14.0%（28412 行里约 3964 行注释） | 对内核偏低但可接受；真正缺的是**模块级"为什么"**（如 SVC 号语义没有一张表） |

核对命令（两条，都在仓库根目录跑）：

```bash
# 1) 函数长度分布：列首函数名 + 五行内找到 '{'，向后数到列首 '}' 收尾
py -3 tools/doc_audit.py funcs

# 2) 编码分布：能解成 UTF-8 就是 UTF-8，否则按 GBK
py -3 tools/doc_audit.py enc
```

口径说明：`funcs` 只认"函数名与括号在同一行"的写法，多行签名会被漏数，所以数出来
的 **25 个 >120 行**是**下界**（早前一次口径数到 19 个，差异全在这里，不是数字变了）。

## 五、优先级（按"补齐成本 / 收益"排）

1. **静态分析 + 覆盖率接进 `ci_gate`** —— 唯一能自己发现问题的欠账，也是所有其他欠账的放大器。落点：`cppcheck --enable=warning` 跑 `kernelsrc/src`（需先装工具）；宿主测试跑 gcov 并设一条"不低于当前值"的下限。
2. **远程 CI** —— 把现有 `ci_gate`（22 项）原样搬进 gitee 流水线，让门禁离开某台机器。
3. **拆 `SVC_Server`（代码侧已完成，差上板复验）** —— 1318 → 58 行 + 17 个 handler，纯重构，`ci_gate` 全绿、编译 0/0、`Code` +408 B；**判据未全中**：板上 `sec` 与 `app` 命令行为还没复验（探针不在线），复验通过才关闭本条。
4. **编码统一** —— 22 个 GBK → UTF-8，单独一个提交、只转码不动逻辑；转完把 `encoding` 检查收紧为"只许 UTF-8"。
5. **功能欠账里挑一条真做** —— 按依赖顺序，最划算的是 `mempool` 的 SVC 通道（不需要新硬件），然后是 tickless 上板；以太网要等 PHY 硬件。
